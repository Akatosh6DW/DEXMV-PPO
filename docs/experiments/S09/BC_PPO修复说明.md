# S09：BC+PPO为什么崩，如何修复

本页记录第一轮修复的128初态、三训练种子结果。后续更长预算、PPO保持约束与新初态检查请看[最新结果解读](独立确认解读_2026-10-19.md)，不要将不同测试批次直接合并计算提升。

## 先说清楚本轮在做什么

这轮解决的是“先模仿，再强化学习”的稳定性，不是把BC+PPO悄悄换成残差PPO。
旧S09实验和原始权重不改动，新结果放在 `artifacts/orca_benchmark_suite/S09/bc_repair/`。
完整逐轮失败和成功记录见 [BC修复迭代.md](BC修复迭代.md)。
最终成绩以冻结方案后生成的保留测试报告为准；开发集成绩不能当最终成绩。

用户目标是：明显超过旧版4.17%，并尽可能提高；没有指定80%等硬阈值。
“超过参考回放”是探索目标，而不是偷偷给用户增加的验收条件。

## 本轮完成后的结果

三组独立训练种子，各自最终163840步权重，放到相同的128个未参与本轮调参的随机初态上评估：

| 方法 | 成功率 | 成功/策略-初态执行 |
|---|---:|---:|
| 旧BC+PPO重新测试 | 5.21% | 20/384 |
| 修复后的BC，还没有接PPO | 36.98% | 142/384 |
| 修复后的BC+PPO | 35.42% | 136/384 |
| 校正参考直接回放 | 40.63% | 52/128 |

历史旧版4.17%来自另一批测试初态。本轮直接比较应该看5.21%到35.42%，提高30.21个百分点。
三个修复PPO种子分别37.50%、32.81%、35.94%，不再是旧版两组完全失败、一组偶尔成功的情况。
描述性分层bootstrap给出新旧差值区间约+17.19到+41.67个百分点；只有三个训练种子，不作强统计定理或任意任务保证。

但修复后的PPO比自己的BC起点平均低1.56个百分点，差值区间约-7.81到+5.21个百分点。
配对看，PPO保留121次成功、丢失21次、新增15次。一个种子提高，两个种子下降。
尤其初始模式3，BC的14/66次成功在接PPO后变成0/66，存在局部系统性遗忘，不能说“所有退化都修好了”。
所以严谨结论是：**严重崩溃已经大幅缓解，达到明显超过旧版的阶段目标；PPO稳定带来额外净收益的问题尚未解决。**
也没有证明超过参考回放，更没有证明优于这轮未重新评估的纯PPO或残差PPO。

1280个执行全部保留，初态数组严格配对；保存预览通过独立物理重放，新策略额外通过实际权重重算动作的校验。
审计只覆盖保存的预览全时序，不冒充所有1280条完整轨迹都独立重放。
失败回合最大穿透仍达到12.413mm，成功回合峰值接触力最高18.87N；成功率提高不等于可以直接安全上硬件。
详细CSV、配对得失、接触质量和方向分组见汇报文件夹的 `保留测试/`。

## 任务到底是什么

Orca手抓一个直径53mm、高53mm、质量35g的圆柱。圆柱初始朝向随机，位置在指定中心附近上下左右前后各扰动2mm。
圆柱开始由理想质心吊带支撑，3秒时撤掉支撑；手必须自己抓住。
一回合最多40秒。合格要求：撤掉吊带以后，连续30秒维持拇指与对向手指的指腹接触，而且40秒结束时仍合格。
不能靠桌面等非手支撑；释放后不能残留绳力；初始穿透不能超过1mm，释放后的累计最大穿透不能超过3mm。
合格抓持还要求物体相对初始高度下降小于15mm，拇指与至少一根对向手指的有效接触载荷都大于0.02N。
接触载荷取一个50ms控制周期内各物理子步的最小值，不是碰一下就算抓住。下降达到55mm或偏离初始位置达到120mm会结束回合。
只短暂拿住、最后掉落、靠不合格碰撞撑住，都算失败。原成功标准没有改。

物理积分每5ms一步；策略每50ms输出一次17维目标关节角，所以一次“动作”会同时控制多个关节，不是只动一根手指。
163840步指32个并行环境累计产生的状态转移数，不是163840个回合，也不是网络更新163840次。
按本轮配置，每次收集 `32 * 20 * 4 = 2560` 个交互，再做4遍、每遍4个小批次的更新。
所以163840步对应64次“收集一批再学习”，以及1024次小批次梯度更新；回合数则取决于每回合多早失败，不能直接从步数换成固定回合数。

## 数据从哪里来

沿用已有DexMV处理后的 `relocate-tomato_soup_can.pkl` 第96条序列，选取182到271帧。
原手指尖轨迹经正运动学恢复，再通过逆运动学映射到Orca，经过仿真校正形成六种初始方向模板。
这里的“视频先验”已经变成离线动作轨迹，不是训练或部署时每帧读取RGB图像。
本轮没有新下载视频、没有从新视频重新做视觉提取；目的是固定数据后定位训练问题。

原始示范采集尝试128回合，成功56回合。BC训练42条，验证14条。
训练集六类数量为 `[20,15,1,3,0,3]`，明显不均衡，且第五类没有成功训练示范。
不能说这些数据已经教会了所有朝向。视频来源、重定向、物理校正和RL是不同环节。

## 原来的BC+PPO怎么工作

BC（Behavior Cloning，行为克隆）就是“看老师在某个状态下给出什么动作，用神经网络拟合这个对应关系”。
原BC把当前关节角、速度、当前控制、上一动作、物体状态、时间和触觉等一起输入网络。
BC不靠奖励来学习，而是减小网络输出与示范动作之间的误差。

具体实现拟合tanh前的动作均值：

```text
L_BC = mean[(mu_theta(observation) - atanh(clip(demo_action, -0.995, 0.995)))^2]
```

每批256个样本，前1.5秒采128个，剩余阶段采128个；优化器Adam，BC学习率0.001。
原版本BC更新4000次。然后把学到的策略网络交给PPO，让它在仿真里继续尝试、根据奖励更新参数。
BC只预训练策略，价值网络没有随BC学好；这也是PPO接续初期需要谨慎的背景，但本轮没有单独证明它是主要原因。

## 为什么离线误差小，实际却容易崩

### 问题一：模仿了容易的相关性，没有稳定学会动作过程

示范里“当前关节已经在哪里”和“老师下一步要它去哪里”往往非常接近。
网络可以取得很低的训练误差，却主要依赖当前手部状态。一旦真实执行时偏了一点，后续输入也跟着偏，误差就可能累积。
这是“捷径学习/闭环分布偏移”的解释；以下受控实验支持这个解释，不等于直接读出了网络的全部内部推理。

仅去掉控制历史、增加训练量、加入连续初始轴信息，均没有稳定修好。
加入六类初始模式后，BC仍受随机初始化影响：三个新初始化成功率31.25%、28.125%、3.125%。

### 问题二：PPO的探索和参数更新会破坏已经学到的动作

BC通常先学出一条较精细的动作过程。训练时在动作上加大随机扰动，很容易把手指从接触点上扰开。
之后网络还会更新参数。PPO的概率比裁剪不等于“动作只能改一点”，也不是严格的KL上限。
这轮同一起点对照显示，学习率0.0003会把较好BC从46.875%训到0%；0.00003在同样40960步里保持并升到50%。
但是对差的BC起点，仅把噪声调小并不能修好，所以不能把问题简单归结为一个学习率数值。

## 本轮有效的修改

### 第一步：记住起始抓法类别

根据仿真中测得的圆柱初始轴方向，在六个模板轴中选最接近的一类。
把这个类别编码成六个数，比如第三类是 `[0,0,1,0,0,0]`，这叫one-hot（独热编码）。
这六个数在整回合保持不变，让网络知道开始时选的是哪种抓法。
类别来自初始姿态，不来自成功标签，也不含参考关节角。

这里增加了观测条件，因此最终修复与旧版本不是严格的“只改一个超参数”。
若上硬件，必须用真实视觉/状态估计取得初始轴；本轮使用的是仿真状态，不是已验证的相机识别。

### 第二步：BC先学“哪种抓法、到哪一步”，不要抄当前手姿

BC训练时，仅保留初始模式和阶段/时间输入，即123维输入中的93:113列。
其余输入暂时置零，并把网络第一层对应输入权重也置零。
这很关键：若只屏蔽训练输入，却保留随机权重，部署时恢复实时输入会引入从未训练过的随机影响。
BC训练增加到40000次，学同一批示范，不偷看最终测试。

这一步的BC实际上是学一个“模式+时间 -> 完整关节目标”的函数，本身还不是会处理任意偏差的反馈控制器。
在同32个开发场景上，成功率由全观测BC的31.25%提升到46.875%。
它的离线验证误差反而更大（约0.000438，对照约0.000082），说明不能只盯着BC loss挑模型。

### 第三步：恢复实时反馈，再用小步PPO训练

接PPO后恢复全部123维观测，包括关节、物体状态和模拟触觉；所有网络权重都可以训练，没有把新反馈永久冻结。
初始动作分布标准差0.03，PPO学习率0.00003。
0.03是tanh前动作分布的标准差，不是所有关节都加0.03弧度，也不是整个训练过程固定不变的噪声。
每个确认种子实际训练163840步，用最终检查点，不按测试成绩挑中途最好模型。

主线没有加入示范损失或教师KL；它们是试过但未选入的对照分支。
主线没有改奖励、摩擦、关节范围、悬吊时间、物体位置分布或成功判据。

## 这是不是残差架构

不是。最终执行公式仍是：

```text
normalized_action = tanh(mu_theta(current_state, initial_mode, phase))
target = joint_low + (normalized_action + 1) / 2 * (joint_high - joint_low)
```

完整动作由一个网络给出，随后走原有低层执行器接口。
没有下面这条残差公式：

```text
target = video_reference_target + PPO_correction
```

BC起点来自示范，PPO继续修改同一个网络；学习过示范不等于部署时还在逐步叠加参考。
模式编码只依赖参考模板的方向元数据。完整参考关节轨迹没有逐步加入执行动作。
测试检查保存轨迹的 `video_base` 和 `requested_residual` 全零，以及网络动作到目标角的映射。

## 奖励有没有一边看日志一边改

没有。这个修复分支固定使用原S09-R0奖励：

```text
reward = 0.05 * (
    15 * currently_valid_hold
    - 50 * dropped_or_invalid_terminal
    + 2 * opposing_contact_coverage
    + 2 * approach_score * before_release
)
```

coverage是拇指与对向手指的接触覆盖分数；approach是指尖接近物体的平滑分数。
大模型读取日志后改变的是下一次实验的观测/BC训练配方或PPO超参数，而不是让同一训练中的奖励自动改写。
这是有记录的人工式外层调参，不能称为一个无需人工选择的新自动算法。

## 怎么防止“看起来变好了，其实比较不公平”

1. 开发场景110000--110031用来反复调参，不能当最终测试。
2. 三个新训练种子13101、13102、13103都保留，不挑最好的一次。
3. 完成开发选择后冻结最终权重SHA256，再运行120000--120127这128个未查看过的场景。
4. 旧三个BC+PPO权重也在相同128个场景上重评；旧4.17%仅作历史背景。
5. 新BC与接续PPO成对比较，记录原来成功后来丢掉的回合，以及新学会的回合。
6. 初始状态数组逐项核对一致；保存预览轨迹用独立原生MuJoCo循环重放检查。
7. 三个训练种子和测试初态分层统计，不能把384个策略-场景执行冒充384次独立训练。

描述性置信区间反映当前少量重复下的波动，不是“严格证明对所有抓取任务有效”。
本轮调参尝试多、BC训练量更大，即使最终PPO步数相同，总成本也不与原版本相等。

## 仍然有哪些边界

- 原示范朝向覆盖不均，只有三根手指参与主要重定向拟合，剩余方向/接触恢复可能需要新的有效示范，而不是一味延长训练。
- 32例开发集上超越参考几例，不足以说明总体超过参考，必须看保留集。
- 没有接触力上限作为成功条件；必须同时看所有失败和成功回合的峰值力，不能凭仿真成功直接上硬件。
- 只有当前物体尺寸、质量、摩擦、扰动范围，尚不能外推为任意圆柱或真实视频噪声下的效果。
- 从新RGB视频做视觉提取，是另一个需要来源、标定、重定向和独立测试的实验，不应混进本轮因果判断。

## 实际投入和怎样复现

截至最终候选冻结，30项有完整metrics的开发运行累计记录1,146,880个在线交互步、396,000次BC批次更新；另有一次中断尝试单独保留。
每次BC更新重复采样256个已有状态，不代表新增了256条视频或示范。
这些数字不含原参考构造成本，也不把评估步数当训练步数；完整记录见开发汇总CSV。
最终三个PPO模型每个163840步，但整个修复过程显然不只花了三次训练的成本。

在主工程根目录、`aero_rl`环境运行。输出目录必须不存在，避免覆盖记录。以下是第一种子的复现例子：

```bash
conda activate aero_rl
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
export XLA_PYTHON_CLIENT_PREALLOCATE=false JAX_ENABLE_COMPILATION_CACHE=false

python scripts/run_s09_bc_phase_curriculum.py \
  --input artifacts/orca_benchmark_suite/S09/inputs \
  --output artifacts/orca_benchmark_suite/S09/bc_repair/reproduce_bc_13101 \
  --method guided --dataset artifacts/orca_benchmark_suite/S09/demonstrations/trajectories.npz \
  --seed 13101 --std .03 --bc-updates 40000 --steps 0 \
  --eval-count 32 --eval-start 110000

python scripts/run_s09_bc_trust.py --conditioned --trust-std .03 --trust-weight 0 \
  --input artifacts/orca_benchmark_suite/S09/inputs \
  --output artifacts/orca_benchmark_suite/S09/bc_repair/reproduce_ppo_13101 \
  --method guided \
  --checkpoint artifacts/orca_benchmark_suite/S09/bc_repair/reproduce_bc_13101/step_000000000/params.pkl \
  --seed 13101 --std .03 --learning-rate .00003 --steps 163840 \
  --evals 5 --eval-count 32 --eval-start 110000
```

改变评估次数可能影响训练器的随机数分段，因此复现时保持上述评估节奏。
检查点恢复会重新建立优化器/RNG；本例是BC后开始PPO，不是承诺任意断点恢复与不中断训练逐位相同。
新一轮调参不要继续把120000--120127叫作“未看过的测试集”；那一批只对本轮冻结前未查看。
