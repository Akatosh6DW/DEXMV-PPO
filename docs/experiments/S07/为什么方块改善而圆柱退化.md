# 为什么方块的BC+PPO改善，圆柱却退化？

## 先给判断

**最合理的解释不是“方块就简单、圆柱就难”一句话，而是两者在探索中留下的可学习空间不同，BC数据与训练起点也不同。** 现有实验没有只改形状、其它全部不变，因此不能把所有差异归因于圆柱曲面。

更重要的反例是：方块PPO也偏离了示范动作，但任务表现反而提高。所以“偏离BC”只是变化，不自动等于退化；关键是偏离后有没有进入更可靠的抓持方式。

## 1. 先确认比较的是哪两次实验

这里对照的是修复指腹后的方块 **S05/T10**，与同类修复后的圆柱 **S07/guided_s7102**。不是旧S02/S04，也不是把不同圆柱版本混在一起。

| 项目 | 方块S05 | 圆柱S07 |
|---|---|---|
| 源示范 | HIC20人手跟踪片段 | DexMV处理后Adroit番茄罐序列96 |
| 核心接触要求 | 拇指＋食指末节指腹 | 拇指＋食指＋中指末节指腹 |
| BC执行回合 | 24条 | 11条 |
| 训练/验证回合 | 18/6 | 8/3 |
| BC更新次数 | 4000 | 20000 |
| 该条训练种子 | 5101 | 7102 |
| 在线PPO预算 | 163840步 | 163840步 |
| 学习率/初始std | 1e-4 / 0.1 | 1e-4 / 0.1 |
| 开发评估 | 4初态、5检查点 | 8初态、9检查点 |
| 开发集BC→末次PPO | 25%→100% | 87.5%→0% |
| 物体质量 | 35 g | 35 g |
| 物体摩擦参数 | 1.35 / 0.025 / 0.004 | 相同 |
| 物体碰撞表示 | HIC方块网格 | 解析圆柱 |
| 求解器impratio | 2.2 | 4 |
| 积分器 | implicitfast | implicit |

所以不能说“圆柱用了更大学习率才失败”，这两条对照的学习率数值相同。但也不能说这是只换了一个物体的严格形状消融。当前圆柱改成三指，参考/工作区、源数据、BC训练量、数值设置都变了。

方块最终独立测试中，仅BC为8/32、BC+PPO为32/32。圆柱S07的完整多种子独立结果另列在本轮结果报告；上表是开发曲线，用于解释变化，不拿4例和8例当充分统计结论。

## 2. 新检查：方块也没有一直照抄BC

对每个任务，固定它自己的BC验证观测，比较零PPO步和最后PPO步的控制目标误差：

| 任务 | BC后与动作标签的RMS误差 | PPO最后的RMS误差 | 开发成功率变化 |
|---|---:|---:|---|
| 方块 | 0.003990 rad | 0.053818 rad | 25%→100% |
| 圆柱 | 0.001439 rad | 0.053386 rad | 87.5%→0% |

最终两个误差很接近，但任务表现相反。**这直接反对“只要离示范更远，效果就必定更差”的解释。** 方块里的偏离可能修正了BC误差、增加有效夹紧或进入更稳定区域；圆柱里的偏离可能破坏了三指受力关系。后半句是机制推断，不是已经定位每个关节的因果证据。

这里比较的是各自机器人动作标签，不是同一张真人图片的视觉相似度。验证集、参考和抓法不同，也不能把两个RMS值当成统一的人手重建精度。

明细：[方块固定输入诊断](../../../artifacts/orca_benchmark_suite/S07/bc_cube_diagnosis/checkpoint_drift.csv)、[圆柱固定输入诊断](../../../artifacts/orca_benchmark_suite/S07/bc_diagnosis_7102/checkpoint_drift.csv)。

## 3. 新对照：同样加探索噪声，两者留下的机会不同

保持BC权重不变，不做一次梯度更新，按`std=0.1`随机采样动作：

| 任务 | 严格成功 | 平均最长严格保持 | 平均最长普通保持 |
|---|---:|---:|---:|
| 方块，原4个开发初态 | 0/4 | 0.225 s | 18.525 s |
| 圆柱，原8个开发初态 | 0/8 | 0 s | 0 s |

所以“只有圆柱怕探索、方块完全不怕”也不正确，两者严格判据都被破坏。但方块仍有较长普通保持，说明至少在这组案例中，随机尝试后还可能把物体留在手附近，继续得到接触和接近反馈；圆柱在相同标准差下更容易完全失去普通抓持。

**大胆假设：** 方块的BC起点虽然精度不高，却位于一个更容易通过探索逐步修好的区域；圆柱BC起点虽然确定性成功率高，却更像一条狭窄的可行路径，离开后很难恢复。

这是一个训练可学习性解释，不是说圆柱无法抓。圆柱小噪声`std=0.01`已恢复到5/8，但尚未证明用小噪声重新训练PPO也能稳定改善。两个任务初态数不同、各只有一个BC种子，这个诊断只用于支持和排除机制，不是形状因果证明。

## 4. 几何与三指条件为什么可能影响这么大

在方块平面内部滑动一点，物体面的法向方向仍相同。以轴为Z的理想圆柱为例，表面法向为$(\cos\phi,\sin\phi,0)$，沿圆周移动会同时改变法向。半径26.5 mm时，沿圆周移动2 mm对应约4.3°的法向变化。

这是几何事实，不意味着2 mm位移一定使当前任务失败；是否失败还取决于手指表面、摩擦、接触点和受力裕量。它说明曲面上的位置变化可能同时改变受力方向，不能只看指尖中心偏了多少。

当前圆柱还要求三个指定手指同时合格。即使拇指和食指仍拿着物体，中指短暂卸载也会清空严格连续计时；方块只要求两个指定手指。这使圆柱的成功集合更窄，不能把增加约束造成的难度全归给形状。

要验证几何原因，应在相同手安装、相同求解设置、相同接触规则下控制替换物体，再测参考附近的扰动容许范围。本次没有做这个严格形状消融。

## 5. BC训练量可能造成不同的局部行为

圆柱用更少回合做了5倍BC更新。它的固定验证误差更低、确定性起点更好；这说明不是完全没学会，但不证明它学到了广泛的纠错策略。

**大胆假设：** 圆柱网络更专门地拟合单条轨迹，在偏离参考的状态上更缺少可用行为；方块BC没拟合得那么精确，但场景允许PPO在附近继续找到稳定动作。

这不能直接叫“已证实过拟合”。过拟合需要更多不同参考/初态的验证，最好在同一圆柱任务中只改变BC更新量（如4000与20000），其余条件一致。不能仅凭更新多就认定训练多了不好。

## 6. 优化日志显示，圆柱的更新更异常

方块T10日志的各阶段平均KL约为0.476、0.039、0.040、0.052。圆柱7102早期出现约2.52e5、1.17e8的日志KL，属于非常值得排查的极端分布变化信号。

注意两个不同概念：

- **训练日志KL**：一批在线数据的采样策略与更新策略差多少，反映局部更新行为。
- **固定BC验证KL**：当前网络与最初BC在固定输入上差多少，反映累计变化。

方块最终相对初始BC的固定验证KL反而比圆柱大，却抓得更好。这并不矛盾：逐步走到一个不同但有效的策略，与某些在线更新突然异常，是两件事。

巨大日志KL也可能被极端状态/方差主导。需要保留分位数和梯度/输入统计，才能区分多数状态的改变与少量异常样本。不能把KL当成真实关节角，也不能仅凭一个大数字判定算法实现错误。

## 7. 夹紧力与仿真设置也是可能原因

方块成功策略存在较大的夹紧力，S05长训最后开发评估峰值约32.02 N。圆柱部分干净成功残差检查点峰值只有约6 N量级，姿态和承力方式不同。不是说用力更大就一定更好：方块可能利用较强夹紧获得容错，圆柱上过度挤压却可能改变接触或使物体弹出。

这只是候选解释，比较对象不完全相同，也没有做同力限制对照。不能把仿真中高力维持的方块成功直接说成轻柔、安全、适合硬件。

两者求解器也不同，但圆柱改为implicit是为处理之前发现的数值失稳；不能仅因这项变化就说它导致了退化。主实验保持各自最终版本，后续需要独立的数值一致性检查。

## 8. 最稳妥的结论

目前证据支持这样说：**PPO偏离示范并不是问题本身；问题是偏离后的探索和更新，是否还能留在有用且物理可信的抓持区域。方块在当前配置中能逐渐改成稳定抓法，圆柱的BC起点对探索较脆弱，在线更新又出现异常分布变化，因而更容易丢失技能。**

其中，动作误差变化、噪声对照、日志KL和配置差别是实际数据；“可行区域宽窄”“更依赖轨迹记忆”“夹紧力增加容错”是待验证机制。不能把这些合理推测写成已经被单变量实验完全证明的结论。
