## 1. 项目概述

### 1.1 要解决什么问题

机械手从零开始靠强化学习（RL）学抓取，需要大量试错。人类视频里已经有现成的抓法，但人手和机械手的结构不同，视频也不会直接给出关节目标和接触力。本项目要做的是：

1. 把视频中的人手动作**转换成机械手能执行的参考动作**（简称"先验"）；
2. 再用 **PPO** 在仿真中根据实际接触情况调整这个动作；
3. 比较先验接入 PPO 的不同方式，看哪种学得更快、更稳。

最初的设想是"大的动作由视频决定，细节由 PPO 微调"，对应执行时显式相加的**残差架构**。

### 1.2 对比的方法

| 方法 | 一句话解释 |
|---|---|
| 纯 PPO | 不用视频，从随机网络开始学，作为基线 |
| BC 后 PPO | 先用示范做行为克隆（BC），再用 PPO 继续训练；执行时由一个网络输出完整动作 |
| 参考 + 残差 PPO | 执行时每一步都用"参考动作 + PPO 输出的小修正" |
| 参考回放 | 只播放参考动作、不做修正，用来判断 PPO 到底补上了什么 |
| 仅 BC（诊断用） | 只做行为克隆，不接 PPO |

### 1.3 当前任务

- **手**：Orca 右手，17 个位置执行器，腕座固定，没有机械臂。
- **物体**：53 mm 方块，或直径 53 mm、高 53 mm 的圆柱，质量 35 g。
- **流程**：物体先由托板或吊绳支撑，3 s 时撤掉支撑，之后只能靠手拿住。
- **成功**：40 s 回合内，撤掉支撑后**连续 30 s 严格合格**，且第 40 s 时仍然合格。

### 1.4 现状

- 从视频到严格评估的整条链路已打通。
- 方块任务上，两种融合方法明显优于纯 PPO（见第 8 节 S04）。
- 圆柱和多朝向任务中，能力主要来自参考本身，PPO 在参考之上的额外增益不稳定。
- 当前正在做 S09 的 PPO 增益迭代（第 9 节）。

### 2.3 计算分工

- **物理仿真**：在 CPU 上运行原生 MuJoCo，通过 JAX 回调接入 Brax 训练循环（[orca_native_physics.py](../scripts/orca_native_physics.py)）。早期用过 MJX（GPU 上的 MuJoCo），在 O29 至 O33 阶段改为原生 MuJoCo 回调，以获得双精度、更可复现的接触计算。
- **策略网络和 PPO 更新**：在 GPU 上运行。
- 因此训练时 GPU 占用率低是正常的，不代表训练没在跑。

### 2.4 脚本中用到的环境变量和 JAX 设置

| 设置 | 在哪里设置 | 作用 |
|---|---|---|
| `XLA_PYTHON_CLIENT_PREALLOCATE=false` | 启动命令或脚本内 | 不让 JAX 预先占满显存，这样才能同时跑多个任务 |
| `XLA_FLAGS=--xla_gpu_exclude_nondeterministic_ops=true` | 启动命令 | 尽量避免 GPU 上不确定的运算，提高可复现性 |
| `jax_default_matmul_precision="highest"` | 训练脚本内的 `jax.config.update` | 矩阵乘法用最高精度，减少数值漂移 |
| `jax_compilation_cache_dir=artifacts/orca30/jax_cache` | 训练脚本内 | JAX 编译缓存，加快重复启动 |
| `jax_pmap_shmap_merge=False` | 训练脚本内 | 兼容当前 JAX 版本的设置 |
| `MUJOCO_GL=egl`、`PYOPENGL_PLATFORM=egl` | 渲染脚本内 | 无显示器时用 EGL 离屏渲染视频 |
| `JAX_PLATFORMS=cpu` | **只用于单元测试** | 强制在 CPU 上跑；正式训练不能设置 |
| `MPLCONFIGDIR` | 画图脚本内 | 避免 matplotlib 写入家目录 |

## 4. 机器人与仿真模型

### 4.1 Orca 右手

### 5.4 逆运动学的数学形式

用 SciPy `least_squares` 求解带上下界的非线性最小二乘，求解器为 TRF（信赖域反射法），雅可比用有限差分估计（`2-point`）：

```text
q* = argmin_{q_min ≤ q ≤ q_max}  ½ ‖ r(q) ‖²
r(q) = [ 指尖位置误差,  a·指腹朝向误差,  b·穿透惩罚,  c·与上一帧的角度差 ]
```

正运动学的做法是：把 q 写入 MuJoCo 的 `qpos`，调用 `mj_forward`，再读取几何位置和朝向。详见 [逆运动学与参考生成原理](experiments/S08/逆运动学与参考生成原理.md)。

## 6. 算法设计

### 6.1 四种方法的动作公式

设 `o_t` 为当前观测，`π` 为策略网络，`q_ref(t)` 为参考目标，`[l, h]` 为关节范围。

| 方法 | 代码中的 `--method` | 执行目标 |
|---|---|---|
| 纯 PPO | `ppo` | `q = l + (π(o_t) + 1)/2 · (h − l)` |
| BC 后 PPO | `guided` | 同上（网络先经 BC 初始化） |
| 参考 + 残差 PPO | `residual` | `q = clip(q_ref(t) + 0.08·clip(π(o_t), −1, 1), l, h)` |
| 参考回放 | `reference` | `q = q_ref(t)` |

四组之后都经过同一步限速：`q_exec = clip(q, q_prev − 0.1, q_prev + 0.1)`，即每 50 ms 每个关节最多变化 0.1 rad。

关键细节：
- **参考自己也先限速**：读取参考时先按控制时刻插值，再单独做一次限速（`load_reference`），然后才加残差。这样 PPO 无法通过逐步累积修正量把手"拖"走参考。
- **每步重新围绕参考修正**：修正量不会跨时刻累加，每一步都是在新的 `q_ref(t)` 附近修正。
- **日志记录 4 个量**：`video_base`（参考）、`requested_residual`（请求的修正）、`desired_ctrl`（限位后的目标）、`effective_residual`（实际执行目标减参考）。
- **修正上限**：0.08 rad 约 4.6°，指单个关节的上限；HIC53 和 F01 实验用过 0.15 rad。

### 6.2 网络结构

- actor 和 critic 都是两层 128 隐藏单元的 MLP（`train_orca_comparison.network_factory`）。
- 采用非对称 actor-critic：critic 能看到额外的执行器力，部署时只用 actor。
- 动作分布是 tanh 变换后的高斯分布，评估时用确定性均值。

**actor 观测（123 维，S09）：**

| 切片 | 内容 |
|---|---|
| 0:17 | 归一化的关节位置 |
| 17:34 | 关节速度 × 0.1，截断到 [−5, 5] |
| 34:51 | 上一步实际执行的关节目标 |
| 51:68 | 上一步的网络动作 |
| 68:71 | 物体相对场景中心的位置 × 20 |
| 71:74 | 物体线速度 × 2 |
| 74:78 | 圆柱轴方向（无向，3 维）+ 1 个占位零 |
| 78:93 | 5 个指尖相对物体的位置 × 10 |
| 93:95 | 释放阶段进度 + 1 个占位零 |
| 95:112 | 当前归一化参考（只有残差组有值，其他组为 0） |
| 112:113 | 回合时间进度 |
| 113:123 | 模拟触觉：5 个力通道 + 5 个接触标志，带噪声、滤波和一个控制周期的延迟 |

critic 观测为上述 123 维再加 17 维执行器力，共 140 维。

### 6.3 PPO 超参数

PPO 直接调用 Brax 的 `ppo.train`，没有自己实现。

| 参数 | S02 至 S08（方块和圆柱基准） | S09 |
|---|---|---|
| 在线交互步数 | 163840（F01 正式实验为 655360） | 163840 |
| 并行环境数 | 128 | 32 |
| `batch_size` / `unroll_length` | 128 / 20 | 32 / 20 |
| `num_minibatches` / `num_updates_per_batch` | 4 / 4 | 4 / 4 |
| 折扣 γ / GAE λ | 0.99 / 0.95 | 0.99 / 0.95 |
| 裁剪 ε | 0.3（Brax 默认） | 0.3 |
| 熵系数 | 1e-3 | 1e-4 |
| 观测归一化 / 奖励缩放 | 关闭 / 1 | 关闭 / 1 |

**S09 中 163840 步的拆解：**
- 每轮采集 `32 × 4 × 20 = 2560` 次交互，163840 步即 64 轮。
- 每轮做 4 个 minibatch × 4 遍更新，共 16 次梯度更新，全程合计 1024 次。
- 每 40960 步做一次开发评估，包括第 0 步共 5 次。

**各方法的学习率和初始探索标准差：**

| 方法 | S02 配方 | S04 调优配方 | S09-R0 |
|---|---|---|---|
| 纯 PPO | lr 3e-4，std 0.7，shaping 1 | 相同 | lr 3e-4，std 0.3 |
| BC 后 PPO | lr 3e-5，std 0.3，shaping 1 | lr 7.5e-6，std 0.3，shaping 1 | lr 3e-5，std 0.3 |
| 残差 PPO | lr 3e-4，std 0.3，shaping 1 | lr 3e-4，std 0.7，shaping 0 | lr 3e-4，std 0.3 |

std 是初始动作分布的标准差，不是物体位置扰动；shaping 是前 3 s 辅助奖励的开关。不同方法用了不同配方，所以对比的是"整套方法"，不是只改一个变量的消融。

### 6.4 BC（行为克隆）

- **损失**：拟合 tanh 之前的动作均值：

  ```text
  L_BC = mean[ (μ_θ(o) − atanh(clip(a_demo, −0.995, 0.995)))² ]
  ```

- **优化**：Adam，学习率 1e-3，每批 256 个样本，其中前 1.5 s 的接近阶段和之后的保持阶段各取 128 个，避免长时间的保持数据淹没短暂的合拢过程。
- **更新次数**：S02 至 S09-R0 为 4000 次，S08 为 20000 次。
- **数据划分**：按整条回合划分训练集和验证集，不按帧划分。
- 只预训练 actor；critic 保持随机初始化。后面的 E 系列实验发现这一点会影响 PPO 刚接手时的稳定性。
- 代码见 `train_orca_matched.fit_matched_bc`。

**S09 BC 修复版（10-15，[BC_PPO修复说明](experiments/S09/BC_PPO修复说明.md)）：**

1. **模板条件**：观测中加入初始朝向模板的 one-hot 编码，整回合保持不变。
2. **输入课程**：BC 阶段只保留"模板 + 时间"两类输入（第 93 至 113 列），其余输入置零，同时把第一层对应的权重清零；训练 40000 次更新。
3. **接 PPO**：恢复全部 123 维输入，std 0.03，学习率 3e-5。

### 6.5 奖励

奖励只在训练中使用，判断成功另有独立的判据（6.6 节）。

**S02 至 S04（方块）：**

```text
r = 0.05 × (15·有效保持 − 50·终止)
  + 前 3 s 的辅助项：0.05 × shaping × (3·接近程度 + 2·拇指接触 + 2·配对接触)
```

代码有继承层次：`orca_benchmark_env.py` 中的历史奖励会被 `orca_refit_env.py` 覆盖，再由 `orca_acquisition_env.py` 加入前期辅助项。不要把每一层出现的奖励项加起来理解。

**S09-R0：**

```text
r = 0.05 × (15·严格抓稳 − 50·掉落终止 + 2·对向接触覆盖 + 2·释放前接近程度)
```

两种奖励中都**没有**"动作像不像视频"的项。S09 的奖励迭代（R1 穿透惩罚、R2 连续保持进度、R4 中断扣分、R5 运动稳定性）都另开编号，见 8.10 节。

### 6.6 成功判据

| 版本 | 适用实验 | 要求 |
|---|---|---|
| 原始成功 | S02 至 S04 | 撤托后连续有效保持至少 30 s，且第 40 s 仍有效。有效指拇指与另一手指配对接触、物体没有明显下落、没有禁止的接触 |
| 清洁成功 | S02 至 S04 主指标 | 原始成功，并且撤托后每个 5 ms 子步都没有禁止的接触、手物穿透不超过 3 mm |
| 指腹判据 | S05 起 | 承力必须落在末节指腹，按局部法向判定，排除指侧接触 |
| 包覆判据 | S08 | 掌面、拇指和其余四指中至少两指的掌侧都承力超过 0.02 N |
| S09 判据 | S09 | 释放后，拇指和至少一根对向手指的掌侧末节或近节都承力超过 0.02 N（取 50 ms 内各子步的最小值），允许掌部辅助但不能只靠掌部托住；初始穿透 ≤ 1 mm，释放后 ≤ 3 mm；高度下降 < 15 mm；绳力为 0；没有非手部支撑；下降 55 mm 或偏移 120 mm 时提前结束回合 |

代码实际判定的是 `best_hold ≥ 30 s` 且 `final_valid`，即回合中曾经连续合格 30 s，并且最后一帧合格。不要求"最后 30 s 逐帧合格"。

## 7. 实验方法

### 7.1 设计原则

1. **区分开发和正式比较**：开发阶段可以改奖励、模型、判据和超参数；正式比较前必须冻结，冻结后不再改。
2. **冻结协议**：把模型、参考、示范、奖励、超参数和文件的 SHA256 写入 `protocol.json`；每次运行还要把源码快照存进 `sources/`。
3. **只改一个变量**：每次迭代只改一个因素，并记录 first / last / max / best_step。
4. **保留失败**：失败、退化和负结果都保留；新版本另起编号，不覆盖旧结果。

### 7.2 种子与数据划分（以 S09 为例）

| 用途 | 种子 |
|---|---|
| 训练种子 | 9101、9102、9103 |
| 开发监测 | 92000 至 92007（8 例） |
| 示范采集 | 90500 至 90627（128 例） |
| 最终测试：随机朝向 | 93000 起 128 例 |
| 最终测试：虎口方向、世界 X、Y、Z 轴 | 分别从 94000、95000、96000、97000 起各 32 例 |
| BC 修复的保留测试 | 120000 至 120127 |
| PPO 增益迭代的开发集 | 130000 至 130063（64 例） |
| PPO 增益迭代的最终保留集 | 150000 至 150127，**还没有用过** |

S02 使用训练种子 1001 至 1010、测试初态 40000 至 40199；S04 使用训练种子 21001 至 21010、测试初态 81000 至 81099。

### 7.3 统计方法

- 先在每个训练种子内算成功率，再跨种子汇总，报告均值、种子标准差和最低/最高种子。
- 同一模型测多个初态，**不能**当作多次独立训练。
- 配对比较：所有方法在同一批初态上测试，报告逐种子差值、分层 bootstrap 95% 区间和精确检验的 p 值。
- 多重比较用 Holm 校正：S02 校正 5 项（Holm-5），S04 校正 2 项（Holm-2）。
- 参考回放是确定性控制器，没有训练种子，不能复制成多份充当独立训练。
- 除了成功率，还报告 15 s 成功率、最长保持时长、穿透、峰值接触力、残差幅度和按朝向分层的成功率。

### 7.4 审计与核验

- **子步审计**：每个 5 ms 子步检查接触部位、法向载荷、穿透和禁止接触，避免"碰一下就算抓住"。
- **原生回放核验**：用原生 MuJoCo 重放保存的轨迹，确认记录的动作确实产生记录的状态；残差组还要检查合成加法和限幅。
- **权重重算**（`audit_s09_ppo_improvement.py`）：用保存的权重重新推理动作，核对参考模板，再做原生回放。
- **不轻信成功标签**：`analyze_*` 脚本会根据保存的高度、承力和穿透重新计算成功与否。
- **单元测试**：S09 目前共 67 项。

### 7.5 视频

- 按固定规则选择回合，不挑最好的种子；成功和失败都导出。
- 默认用手心视角（相机旋转 180°），碰撞几何版和 STL 外观版各一份。
- 相关脚本：`render_s09_trace.py`、`export_s09_showcase.py`。展示视频通常只截取前几秒，是否成功以完整 40 s 的评估为准。

### 8.10 S09 PPO 增益迭代（10-18，进行中）

- **目标**：让 PPO 在自己的起点（BC 或零修正参考）之上真正提高。
- **设置**：开发集 64 例（130000 至 130063）。BC 起点使用修复后的检查点 I26、I27、I28；零修正参考在开发集上是 29/64 = 45.31%。

| 编号 | 方法 | 改动 | 末步结果（起点 → 末步） | 结论 |
|---|---|---|---|---|
| E01/E02 | BC | γ 0.99 改为 0.999 | 32.8 → 31.3 / 31.3 | 长折扣无效 |
| E03/E04 | 残差 | 同上 | 45.3 → 43.8 / 39.1 | 无效 |
| E05/E06 | BC / 残差 | R2 连续保持进度奖励 | 31.3 / 40.6 | 无效 |
| N01–N03 | BC（不训练） | 执行时的探索标准差 0.03 / 0.01 / 0.003 | 确定性执行 9/32；随机执行分别 3/32、7/32、9/32 | 探索噪声会把已经学会的抓法扰坏 |
| E07–E09 | BC | 探索标准差 × 学习率的 2×2 对照 | 25.0 / 32.8 / 32.8 | 只缩小噪声会让 KL 爆炸；同时降学习率只能保住起点 |
| E10–E12 | 残差 | 同上 | 45.3 / 45.3 / 42.2 | 中途有收益，末步保不住 |
| E13 | BC | 快 critic（3e-4）+ 慢 actor（3e-6） | 32.8 → **37.5** | 短训正候选 |
| E14/E15 | BC | 训练时加冻结 BC 的 KL 约束，λ = 0.1 / 1 | **39.1** / 32.8 | 弱约束是正候选，强约束不敢改 |
| E16/E17 | BC / 残差 | 修复 Brax 自动重置覆盖 truncation 的问题 | 37.5 / 37.5 | BC 有净增益，残差退化 |
| E24 / E30 / E32 | BC | 快 critic 配方、三个 BC 起点长训到累计 655360 步 | 3 组合计从 BC 起点的 38.0% 到 41.1%（+3.1 个百分点） | 有小幅净增益，但后段会回落 |
| E36/E38 | BC | 先用 Monte Carlo 回报预训练 critic（短训 / 长训），起点 40.6 | 39.1 / 40.6 | 减轻退化，但没超过 BC |
| E37/E40 | 残差 | R4 中断扣分（短训 / 长训） | 46.9 / 42.2 | 短训的收益在长训中没保住 |
| E43/E45 | 残差 | 80 步长片段（短训 / 长训） | 48.4 / 40.6 | 同上 |
| E44/E47 | BC / 残差 | R5 运动稳定性奖励 | 35.9 / 46.9 | BC 无效；残差只多 1 例 |
| E48 | BC | 冻结 BC 骨干，只训练反馈连接 | 35.9 | 无效：参数固定不等于行为不变 |
| E46、E49、E50 | — | 追加预算、残差 R5 长训、只在起手阶段降低探索噪声 | 运行中 | — |

**阶段性结论：**
- BC 后 PPO：最可靠的方向是"慢 actor、快 critic、低噪声、加长训练"，三个种子的净增益约为 +3 个百分点。
- 残差：所有尝试在长训末步都没有稳定超过参考。
- 另一个发现：参考控制路径上约 1e-7 rad 的浮点差异，就能改变个别临界回合的结果，所以相差一两例不能当作有效收益。

| `--method` | `ppo`、`guided`、`residual`、`reference`、`collect`、`bc` |

| `--checkpoint` / `--dataset` | 初始化权重 / BC 示范 |
| `--allow-cpu` | 允许在没有 GPU 时运行（只用于冒烟测试） |

## 11. 已知问题与注意事项

### 11.1 环境和工程

1. **磁盘几乎满了**：系统盘只剩约 1.6 GB，后台还有 3 个训练在写文件，随时可能因为写不进去而失败。可以清理的大户是 `artifacts/orca_formal/`（33 GB）和 `deliverables/` 中的 zip（约 7 GB）。删除前务必确认已经备份。
2. **`playground` 包的安装路径失效**：`pip list` 显示它装在 `/home/ll/SRTP/Aero-Hand/...`，但这个目录已经不存在了。所以直接 `import mujoco_playground` 会报错。训练脚本内部会执行 `sys.path.insert(0, ROOT/"Aero-Hand/sim_rl/mujoco_playground")`，因此能正常运行；自己写脚本或在交互环境里使用时，要设置 `PYTHONPATH`。
3. **场景 XML 写死了绝对路径**：`S09/inputs/model.xml` 等文件通过绝对路径引用 `/home/ll/SRTP/DEXMV-PPO/artifacts/orca_collision_refit/G06_*` 下的 STL。换路径或换机器后需要改路径或重新生成场景。
4. **代码几乎没进版本管理**（详见 12 节第 1 条）。
5. **一部分代码修改在子模块里**：Orca 基础环境在 Aero-Hand 子模块中，而且还是未跟踪状态。

### 11.2 数值和复现

6. **GPU 和接触的可复现性有限**：同一个种子在不同 GPU 或软件版本上，轨迹不保证逐位相同；处在接触临界的回合可能被约 1e-7 rad 的差异翻转结果。
7. **Brax 随机流和评估间隔有关**：改变 `--evals` 会改变随机数的分段，即使种子相同，训练前缀也不完全一样。
8. **Brax 自动重置会覆盖 `truncation` 和回合统计**：只在 `run_s09_transition_ppo.py` 里修复了，历史实验仍是旧行为。
9. **从检查点恢复时不带 Adam 状态**：续训等于用重置的优化器开始新阶段，不是一次不中断的长训。

### 11.3 读结果时容易误解的地方

10. 代码里 `guided` 就是 BC 后 PPO，`residual` 才是执行时相加的残差。`guided` 的 `step_000000000` 表示 BC 已完成、PPO 还没开始。
11. 字段名 `cube_z`、`video_base`、`pad_hold_sec` 是沿用的旧名字：S08 中的 `video_base` 其实是几何参考，S09 中的 cube 其实是圆柱。
12. `summary.json` 存在只说明这个任务跑完了，不代表整个实验完成；还要核对独立评估、配对初态、哈希和轨迹复算。
13. "相同在线步数"不等于"相同总成本"：参考校正、IK 和 BC 的计算量没有算在 PPO 步数里。例如 S09 准备参考时额外做了 2561 次回放，约 40 万个控制步。

3. **修复环境的可移植性**：重新以可编辑方式安装 playground 并指向子模块路径；场景 XML 改用相对路径的 `meshdir`；在主仓库根目录放一份 `aero_rl` 和 `dexmv` 环境的导出文件。

   - 把环境、残差合成、原生物理、评估、统计抽成一个公共包。
   - 每轮实验只保留配置和入口，按 `experiments/S09/` 这样的结构分目录。
   - 统一字段名，例如把 `cube` 改成 `object`。
5. **提供一键复现入口**：为当前主线写一个总 README 或 Makefile，从参考生成一直串到统计。

### 12.2 研究方向

6. **参考覆盖不足**：S09 只有 6 个模板，竖直方向几乎全部失败；无名指和小指的参考为 0，修正范围又只有 ±0.08 rad，实际上只能做三指抓。可以考虑增加模板、做随朝向连续变化的条件参考、做五指参考，或者按阶段放宽修正上限。
7. **视频来源单一**：只用了 HIC20 和 DexMV 序列 96，圆柱示范与原始 RGB 的对应关系也没有核实。要讨论泛化，就需要多段独立视频、按视频划分训练和测试集，并且真正从 RGB 跑一遍手部姿态估计。
8. **PPO 在先验之上的增益不稳定**：残差在长训中一直没有稳定超过参考；BC 后 PPO 有遗忘。E 系列里的正候选（快 critic 慢 actor、弱 KL、critic 预训练）需要在保留集上用多个种子确认。还可以考虑残差正则、置信门控、DAgger 式纠偏示范。
9. **闭环反馈的作用没被证实**：缺少"实时残差"和"同一组修正量固定回放"在相同扰动下的配对对比，所以还不能说提升来自实时纠错。
10. **基线公平性**：纯 PPO 的调参投入少于融合方法，缺少"相同调参预算"的比较；离线校正和 BC 的成本没有统一记账。
11. **离真机还很远**：
    - 质量和摩擦是假设值，手指自碰撞没有完整启用。
    - 峰值接触力可达 100 至 200 N，成功判据没有限制它。
    - 物体位姿、触觉都来自仿真真值。
    - 上真机还需要状态估计、传感器标定、域随机化和安全限幅。

## 14. 术语表

| 术语 | 含义 |
|---|---|
| 先验 / 参考 | 训练前就有的大致动作，这里具体指一张随时间变化的关节目标表 `q_ref(t)` |
| 重定向 | 把一种手的动作转换成另一种手能做的动作 |
| IK（逆运动学） | 已知指尖要到哪里，反过来求关节角 |
| BC（行为克隆） | 照着示范的"状态 → 动作"做监督学习 |
| PPO | 在仿真中试错，按奖励小步更新策略的强化学习算法 |
| 残差 | 执行时加在参考动作上的有界修正量 |
| actor / critic | 输出动作的网络 / 训练时估计长期回报的网络 |
| 回合 / 控制步 / 物理子步 | 一次 40 s 的尝试 / 每 50 ms 发一次动作 / 每 5 ms 推进一次物理 |
| 训练种子 / 测试初态 | 一次独立训练的编号 / 一个测试起始状态的编号 |
| 检查点 | 训练到某一步时保存的参数 |
| 开发集 / 保留集 | 调参时看的初态 / 方案冻结后才看的初态 |
| 消融 | 只拿掉一个部件，看它的作用 |
| 清洁成功 | 原始成功，并且通过子步接触和穿透审计 |
| Holm 校正 | 同时检验多个比较时，对 p 值做的保守修正 |
| SHA256 / 哈希 | 文件内容的指纹，用来核对文件有没有被改过 |
