# 汇报资料里的数据怎么读

本资料包用于理解实验、做图、核对结论。不带神经网络权重、完整STL资产和conda环境，因此不是拷走即可训练或部署的工程。原工程未移动，也未删除。

## 先分清四类东西

| 文件 | 人话解释 | 能做什么 |
|---|---|---|
| 参考NPZ | 每个时刻希望手指到达什么角度的动作表 | 看基础抓法；作为BC示范采集或残差基础动作的来源 |
| 示范NPZ | 参考在仿真里成功执行后留下的“当时看见什么、应该做什么” | 训练BC；不是只有一个起手姿势 |
| 评估NPZ | 某个固定策略实际尝试抓取时的逐时刻记录 | 复算保持时间、接触、控制，绘图和重现画面 |
| 权重PKL | 策略网络学到的参数 | 配合环境执行策略；本包按要求不附 |

NPZ是压缩数组容器，不是算法名称，也不天然等于数据集或权重。本工程这些NPZ主要存动作、状态和接触记录。它们可能比神经网络权重更大。

## 来源证据在哪里

- S05的直接输入是HIC20人类跟踪点整理出的`source_correspondence.npz`，代码从中读取物体局部坐标下的拇指/食指点，拟合Orca抓法。资料包的`S05/来源证据/`附原始RGB示例、处理后人类点、物体对应信息；其中`adroit_cube.npz`是早期链路中间产物，不表示最新S05必须先控制Adroit再控制Orca。
- S06/S07实际使用的是官方处理后的Adroit罐体序列96的182～271帧。`S06/来源证据/selection96/selected_segment.npz`保存选用片段，S07复用它。尚未核实该序列对应的原始RGB，不把重建的Adroit画面冒充真人原视频。
- S08本轮使用P03几何求解与摆位修复后的参考，没有新的人类视频输入。新采集的30条成功示范是同一几何参考在不同仿真初态下的执行，不是30段人类视频。

## S08几个最常用的文件

### 1. `inputs/reference.npz`

本轮`ctrl`是31行、每行17个关节目标角度；`time`是对应的31个时间点，覆盖起手闭合。之后保持终点目标。

- `time`：秒。
- `ctrl`：弧度，不是力矩，也不是PPO输出的归一化动作。
- `initial_ctrl`：初始17关节目标。
- `object_position`：物体初始世界坐标，单位米；不是屏幕的左右上下。
- `object_quaternion`：物体body的wxyz四元数。实际几何方向还需乘上geom局部旋转，见[坐标核对](姿态坐标核对.md)。

### 2. `demonstrations/trajectories.npz`

本轮采集32次，保留30条严格成功轨迹作为示范；原始采集失败仍保存在采集目录中。

- `obs`：`30 × 800 × 123`，每条轨迹每个时刻的策略观测。
- `action`：`30 × 800 × 17`，与观测对应的归一化动作。
- `active`：`30 × 800`，标明实际有效执行的时刻，防止把结束后填充帧当样本。

BC按完整轨迹分割：前22条训练，后8条验证，不把相邻帧打散后冒充独立验证。20000次BC更新不等于20000段视频，也不是PPO在线交互步。

### 3. `eval/条件/方法/step_000000000/`

这里的`step_000000000`表示“加载冻结权重后直接评估，不做新的训练”，**不表示所加载的模型从未经过PPO训练**。看同目录上一级`run_config.json`中的`checkpoint`和冻结`selection.json`才能知道权重来自哪一步。

| 文件 | 含义 |
|---|---|
| `episodes.json` | 该策略在这个条件下每个测试初态的完整结果 |
| `initial_states.npz` | 所有测试初态及种子；用于确认方法之间起点一致 |
| `preview_trajectories.npz` | 保存下来的逐时刻状态、动作和接触，名字叫preview不代表只跑了几秒 |
| 上一级`run_config.json` | 方法、权重来源及哈希、模型、参考、种子、运行代码快照哈希 |
| 上一级`env_config.json` | 实际测试条件，例如摩擦、质量、扰动范围和残差增益 |

正常条件与消融保存全部轨迹；其它扰动每个策略保存前4条轨迹，其余仍保留每回合结果和初态。S08总计3424回合，其中1604条可逐帧离线复算，不能说本包保存了3424条完整逐帧轨迹。

## 一条评估轨迹的字段

第一个维度是回合，第二个维度是时刻。一个完整回合800个控制步，每步50 ms，共40秒；另有初态文件保存0秒的状态。

| 字段 | 怎么理解 |
|---|---|
| `qpos`、`qvel` | 实际关节与物体位置/速度；qpos还含物体四元数，不是所有列都用弧度 |
| `action` | 策略输出的17维归一化动作；残差策略下它表达修正，不是完整角度 |
| `ctrl` | 经范围和变化速度约束后，真正交给执行器的关节目标角 |
| `video_base` | 当步参考目标。S08沿用旧字段名，实际是几何参考，不表示正在读取RGB |
| `requested_residual` | PPO请求的修正，弧度；本轮每关节不超过0.08 rad |
| `effective_residual` | 实际`ctrl - video_base`，包含关节裁剪和限速影响，不能与请求修正混为一谈 |
| `wrap_loads` | 六组掌侧曲面法向载荷，顺序为掌、拇指、食指、中指、无名指、小指，单位牛顿；取50 ms内最小值 |
| `substep_penetration` | 当前控制区间的最大穿透，单位米，不是毫米 |
| `substep_forbidden` | 当前控制区间是否出现禁止承托接触 |
| `cube_z`、`spawn_z` | 物体当前和初始高度，单位米；S08虽然字段仍叫cube，实际物体是圆柱 |
| `hold` | 当前连续合格保持的秒数，不合格就清零；不是累计所有零散成功片段 |
| `active`、`alive` | 当前帧是否实际执行，以及执行后回合是否仍存活；结束后填充的重复状态不能重复计分 |

接触、穿透在每个5 ms物理子步检查，区间记录最小承力和最大穿透，避免只看控制步末尾漏掉短暂失稳。轨迹复算是根据这些已保存的子步汇总、位置和存活标记重新计算判据，不等于从压缩后的qpos重新完整模拟每条轨迹。

## 报告中的统计表

- `episodes.csv`：一行一个方法实例、条件、初态的结果。最终做汇总应以此表及对应原始JSON为依据。
- `policy_summary.csv`：一个训练种子对应一个固定策略的统计，包含成功数、分母及Wilson区间。
- `aggregate.csv`：同方法三个训练种子的均值和样本标准差；固定参考只有一条，不能虚构三个参考训练种子。
- `paired_changes.csv`：同一初态的救回、破坏与平局。不要把三组共用的参考当作三套独立数据。
- `training_diagnosis.csv`：训练开始、最后、最好、选中进度，BC误差与KL。最大KL是已记录指标中的最大值，不是保存了每次梯度更新的瞬时最大值。
- `nominal_failure_modes.csv`：正常条件的失败表现；掉落、缺承力、高度超限等标签可能重叠，不能直接相加当失败总数。
- `verification.json`：完成数量、来源校验、配对和控制重组检查；仅有某个run的`summary.json`不代表整套实验已经完成。

64个初态不是64次独立训练；800帧也不是800个独立样本。跨S05～S08的任务判据不同，百分比只能在各自条件下解读，不能简单相减当算法提升。

## 视频与原始统计的关系

主要展示视频只用手心视角，外观和碰撞几何各一版。成功片剪到连续拿稳4秒；完整成功依据40秒评估中的30秒保持。失败片在终止或明确丢失有效抓持时结束，未提前终止但不合格的案例会保留到评估结束并标记失败。

展示回合按目录中的固定规则选取，并非随机抽样。不要根据一条视频判断总体成功率。原始HIC RGB、几何参考回放、BC、BC+PPO和残差PPO在命名和目录中分开说明。
