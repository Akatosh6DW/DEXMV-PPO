# 残差PPO的输入，是不是BC网络的输出？

## 一句话回答

**可以这样设计，但我们当前这套不是。** 当前PPO输入中有“基准动作”，它来自校正后的参考`.npz`，不是BC网络。残差的关键也不是某项输入来自谁，而是最终执行动作必须显式地由“基准＋修正”组成。

## 1. 当前实际运行的架构

```text
处理后的示范 -> Orca重定向 -> 仿真校正 -> reference.npz
                                                |
                                         读取本步基准 b_t
                                                |
当前手/物体/触觉状态 + 当前基准 + 时间进度 -> PPO -> 修正量 Δ_t
                                                |
                           最终目标 = 基准 b_t + 修正量 Δ_t
                                                |
                           关节范围裁剪、目标变化限速 -> 执行器
```

数学上：

$$
b_t=\mathrm{Reference}(t)
$$

$$
\Delta_t=0.08\,\mathrm{clip}\left(\pi_{res}([s_t,b_t,\phi_t]),-1,1\right)
$$

$$
u_t=\mathrm{Limit}(b_t+\Delta_t)
$$

$s_t$表示任务状态与触觉等信息，$\phi_t$表示时间进度，`Limit`表示关节范围和变化速度限制。代码会将放入观测的基准角归一化，而合成动作时用弧度；两者含义相同，数值单位不同。

**基准走两条路：一条让PPO知道原本准备怎么动；另一条直接参与最后的相加。** 因而它不是只在训练时提供启发，也不是仅设置起手姿态。

当前执行阶段没有一个BC网络专门产生基准。残差策略来自零修正初始化和PPO训练，BC+PPO是另一个对照分支，两者不是自动串在一起的。

## 2. 你说的“BC输出给PPO”，可以做成另一种残差

```text
当前状态 -> 冻结的BC网络 -> 基准动作 b_BC
                              |
当前状态 + b_BC -> PPO -> 修正 Δ
                              |
                  最终目标 = b_BC + Δ -> 限幅限速 -> 执行
```

公式是：

$$
b_t=\pi_{BC}(s_t),\qquad
\Delta_t=\alpha\pi_{res}([s_t,b_t]),\qquad
u_t=\mathrm{Limit}(b_t+\Delta_t)
$$

这可以叫**“BC基准策略＋残差PPO”**。BC网络先通过示范学会大致动作，PPO再根据状态修正。一般先冻结BC，让PPO面对稳定的基准；若两个网络同时更新，需要另外设计训练和约束，不能默认更好。

这里喂给PPO的是BC在当前状态下输出的动作，不是把BC的整套网络权重作为输入。也不是把两个动作直接拼成一个34维控制命令。

## 3. 只把BC输出当输入，还不一定是残差

如果写成：

$$
u_t=\pi_{PPO}([s_t,\pi_{BC}(s_t)])
$$

然后直接执行$u_t$，那是“带BC建议输入的PPO”。它可以忽略BC建议、重新输出整套动作，没有显式“基准＋有界修正”。这不是本项目强调的严格残差执行结构。

所以判断方式很简单：**看执行器前最后一步是否真的把基准加回来，而不是只看PPO输入里有没有BC或视频特征。**

## 4. 与当前BC+PPO对照的区别

| 方式 | BC在哪里 | 执行时是否有独立基准 | PPO控制什么 |
|---|---|---|---|
| 纯PPO | 不用BC | 没有 | 全部关节目标 |
| 当前BC+PPO | 预训练动作网络，随后PPO继续改这个网络 | 没有独立BC分支 | 全部关节目标 |
| 当前参考残差 | 不用BC初始化残差策略 | `.npz`按时间给出基准 | 有界修正 |
| 可扩展的BC残差 | BC网络保留并通常冻结 | BC根据状态产生基准 | 有界修正 |

当前“BC+PPO”不是“BC网络每步输出一次、PPO再加一次”的意思，而是同一个动作网络先接受监督学习、再接受强化学习。

## 5. BC作为基准会不会更好

有可能，但不能直接保证。

- 固定参考的优点是来源和动作变化都容易检查，不会因为新状态使基准网络输出失常；缺点是大幅移动物体后参考可能不合适。
- BC基准可以随当前物体和手的状态改变，更像反馈策略；但如果只学过单一参考附近的数据，遇到滑落状态也可能给出错误基准。
- 即使PPO修正上限仍为0.08 rad，**BC基准本身也可能大幅改变**。只限制修正，不能保证整体动作一定温和。
- 当前BC在有随机扰动时已经暴露出脆弱性，所以应先验证其基准稳定性，再做这一扩展，而不是把它换进去后自然期待解决问题。

实现时还要统一动作单位和观测接口。当前BC分支的参考输入槽是零，残差分支则填入基准角；不能把残差观测原封不动喂给旧BC模型，造成它从未见过的输入。BC若输出归一化动作，应先转成关节目标弧度，再与同单位修正相加。参考来源改变后也应重新训练和评估残差，不直接沿用旧权重冒充兼容。

## 6. 代码在哪里

- [orca_residual_env.py](../../../scripts/orca_residual_env.py)：`_obs()`将17维基准和进度放进观测；`step()`读取基准并合成修正。
- [orca_residual_controls.py](../../../scripts/orca_residual_controls.py)：`load_reference()`读取`.npz`并重采样；`compose()`计算基准加修正。
- [run_s05_job.py](../../../scripts/run_s05_job.py)：`guided`分支先做BC再PPO；`residual`分支不做BC预训练。

当前观测为123维，其中17维用于残差基准、1维用于进度，其余为手与物体状态、控制历史和仿真触觉等；完整动作方法保留相同维度，但基准槽为零。相同网络大小不等于三种方法获得完全相同的先验信息，这正是实验要比较的差别。
