# 逆运动学与参考生成：原理、算法名称和实验中的位置

核对日期：2026-10-12。本说明对应现有S05至S08源码，不代表新DexMV包覆实验已经完成；本次仅补文档，不修改训练结果或参考动作。

## 1. 一句话先理解

正运动学：知道各关节弯了多少，算指端在哪里。

逆运动学：知道希望指端到哪里，反过来求各关节应该弯多少。

例如“食指接触圆柱右侧，指腹朝向圆柱”是目标；逆运动学负责把这个目标翻译成食指各关节角度。它不是看视频的算法，也不天然知道什么抓法最好。

视频示范可以提供目标，人工规则也可以提供目标。是否使用IK与目标是否来自视频，是两个不同问题。

## 2. 正运动学为什么能算位置

机械手模型记录了各段手指的长度、关节位置、转轴和连接关系。给定角度向量q，沿手指从根部到末端逐节叠加旋转和平移，就能算出末端的位置与朝向。

用两节平面手指举例，长度为L1、L2，关节角为q1、q2：

```text
x = L1*cos(q1) + L2*cos(q1+q2)
y = L1*sin(q1) + L2*sin(q1+q2)
```

这是教学例子，不是Orca实际使用的简化模型。实际代码把角度写入MuJoCo的qpos，调用mj_forward，再读取碰撞代理中心的geom_xpos与手指body的xmat，获得三维位置和朝向。

同一个末端位置可能对应多种关节姿态，也可能根本到不了。所以一般不是把上式简单倒过来就能唯一求解。

## 3. 本项目实际用了哪个算法

分清三个层次：

| 层次 | 名称 | 含义 |
|---|---|---|
| 要解决的问题 | Inverse Kinematics，IK，逆运动学 | 由目标位置/朝向反求关节角 |
| 数学建模方式 | 带变量上下界的非线性最小二乘 | 让位置、朝向、穿透等误差的平方和尽量小 |
| 实际数值求解器 | Trust Region Reflective，TRF，信赖域反射法 | SciPy least_squares在这些调用中采用的默认方法 |

当前aero_rl环境核对为SciPy 1.17.1。所检查的S05、S06和S08调用没有显式指定method、jac、loss，当前安装库的默认值分别为trf、2-point、linear。这里的linear表示普通平方损失，不表示机械手运动是线性的，也不是Huber等稳健损失。

下面是便于阅读的等价写法，不表示历史代码显式写了所有默认参数：

```python
fit = least_squares(
    residual,                   # 给定一组变量，返回各项误差
    x0,                         # 初始猜测
    bounds=(lower, upper),       # 关节角/摆位等变量的上下界
    method="trf",               # 当前调用使用的默认方法
    jac="2-point",              # 数值有限差分估计雅可比矩阵
    loss="linear",              # 普通最小二乘
    max_nfev=160,                # S08初始拟合的函数求值预算
)
```

max_nfev不是PPO步数，也不是严格意义上的“训练160轮”；有限差分估计所需的部分函数调用另计。此处没有训练神经网络。

求解器命名与参数说明可查[SciPy官方文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html)。网页是滚动版本；本工程实际默认值以上述本地1.17.1核对为依据，不据当前安装版本反推所有历史运行都使用同一版本。

## 4. 优化的公式是什么

最简单的IK只处理位置：

$$
q^* = \arg\min_{q_{\min}\le q\le q_{\max}}
\frac{1}{2}\sum_i\|p_i(q)-p_i^{\mathrm{target}}\|^2.
$$

- q：各关节角度，通常用弧度。
- p_i(q)：这组角度下，第i个指端的实际位置。
- p_i^target：希望它到达的位置。
- argmin：寻找让后面误差最小的一组角度，不是另一个算法。

本项目还拼接了其它误差，概括成：

```text
r(x) = [位置差,
        a * 朝向差,
        b * 穿透惩罚,
        c * 与上一帧角度差（使用时）,
        d * 摆位或姿态正则项（使用时）]

目标：在 lower <= x <= upper 内，让 0.5 * sum(r(x)**2) 尽量小。
```

x不一定只有关节角：S08第一阶段同时优化16个手指控制角和圆柱中心的3个坐标，腕目标固定为0；S05/S06的终点拟合也包含工作区摆位/旋转变量。它们因此是“带摆位优化的IK”，不是在任意固定位置都能精确达到目标。

各阶段并非都包含全部项。系数乘在误差向量上，再进入平方和，因此最终平方损失中的权重是系数的平方。不同单位混合后的权衡由这些工程系数决定，不是自动校准的物理定律。

尤其要注意：关节范围由bounds限制，但避免穿透主要靠软惩罚，不是严格无碰撞证明；这也是后面仍需物理回放的原因。

## 5. 求解器怎样一步步找到角度

1. 先猜一组合法角度，用模型算出手指在哪里、朝哪里。
2. 与目标比较，得到位置偏差、朝向偏差等误差。
3. 让一个变量变化极小一点，观察误差如何变化；轮流处理各变量，估计雅可比矩阵。
4. 根据这个局部近似，寻找一小步能减小误差的调整，同时处理变量上下界。
5. 实际重新计算误差。如果效果符合预期，可扩大下一步探索范围；不符合则缩小，再尝试。
6. 达到停止容差或求值预算后停止。脚本通常从多个初值重复求解，再按几何误差或开发回放表现选择。

雅可比矩阵可以理解为一张表：“每个关节轻微转动，会让每项误差改变多少”。这里用的是有限差分估计，不是手工推导的解析雅可比。

“信赖域”指每次只在当前近似较可信的邻域里求一步，不能当作一次无限大的改动；“反射”涉及接近变量边界时的可行步处理。这段是原理概述，不是完整复刻SciPy的内部实现。

局部求解可能落入不同的局部解。多初值能降低对单一起点的依赖，但不能保证全局最优；脚本取得fit.x也不等于已经证明抓取成功。

## 7. S08几何参考具体经过哪几步

1. P01：人为设置五指绕圆柱的方位、高度，求解手指角度与物体中心。位置误差之外，加指腹朝向、穿透、摆位偏移和小幅关节正则项。纵向/横向各6个初值，先短回放选候选。
2. P02：保持其它手指不变，重新求拇指4个控制角，强化曲面朝向；初始物体向掌前移动6 mm。这个朝向修正仍不是PPO。
3. P03：冻结全部控制轨迹，在100个初始位置偏移上筛查穿透并做开发回放，选短回放前5个做完整开发验证；最终选中相对P02抬高12 mm。测试种子不参与选位置。
4. 闭合参考：由张开到最终姿态做1.5秒线性插值，31个采样点，每点17个关节目标，之后保持终点。不是从视频学习到的闭合时序。
5. 物理回放：托板撤下后检查接触载荷、下滑、穿透和持续保持，再决定是否合格。

P03是初始摆位搜索，不是PPO学会抬升圆柱，也不是对每个最终测试样本重新调整位置来保证成功。

## 8. 为什么有IK后还需要PPO

IK主要解决“几何上能不能摆成这个姿势”。它本身不证明摩擦够不够、物体是否滑落、运动中是否撞开物体，或初始位置扰动后是否还稳。

参考回放虽有底层执行器跟踪目标角，但没有根据物体滑动主动改变抓法的高层网络。残差PPO则根据当前观测产生调整：

```text
参考生成阶段：示范/人工目标 -> IK与物理校正 -> 保存b(t)

执行阶段：q_target(t) = b(t) + delta_q_PPO(s_t)
          然后做关节范围与每步变化限幅
```

这里b(t)是预先保存的关节目标表，不是每个执行步都重新运行IK。BC+PPO则先模仿参考执行产生的状态动作对，随后训练完整动作策略，执行时不强制加回b(t)。

两者都不保证优于参考；S08正式结果已经保留残差退化。IK拟合误差、仿真成功率、视频相似程度也是三种不同指标。

## 9. 三个容易混淆的名字

| 名字 | 在这里是什么意思 |
|---|---|
| TRF | 求几何变量的数值优化方法，本工程IK使用它 |
| TRPO | 强化学习策略优化算法，不是本工程IK的求解器 |
| residual误差向量 | least_squares里当前几何解与目标的差，不是Residual PPO输出的动作修正 |

IK不是BC，也不是PPO；TRF不是TRPO。用到了数值迭代，不代表在进行强化学习训练。

## 11. IK能不能成为一个决定姿态的网络

IK就是Inverse Kinematics（逆运动学）的缩写，两者完全是同一个概念。

本工程当前的IK是数值求解程序，不是神经网络。输入目标位置/朝向和机械手模型，经过迭代输出一组关节角；它没有经过BC或PPO学习的网络权重。多次求解保存成动作表，动作表也不会自动变成网络。

但可以增加学习步骤，把IK产生的结果教给网络，至少有两种不同做法：

| 做法 | 输入 | 输出 | 学到了什么 |
|---|---|---|---|
| 神经网络近似IK | 目标指端位置/朝向，必要时加当前关节角 | 满足目标的关节配置 | 近似几何求解器，不自动具备抓稳物体的能力 |
| 用IK生成示范，再做BC | 实际执行时的当前状态/观测，可加任务目标 | 下一步执行器动作 | 模仿示范控制行为的策略 |

同一目标可能有多个合法解。如果不提供当前姿态等消歧信息，网络可能把不同解平均成不合理的角度。还需检查限位、碰撞、可达范围和分布外目标；不能把一个IK近似网络直接当作可靠的抓取策略。

S08已经做的是第二种：几何参考执行后生成示范，再训练BC网络。没有另外训练一个替代TRF求解器的“神经IK网络”。

## 12. BC能不能靠IK实现

可以用IK帮助生成BC的训练样本，但BC本身仍是监督学习，不是由IK替代。

本工程的实际流程是：

```text
人工几何目标
    -> IK算出参考关节角与动作序列
    -> 仿真真实执行，检查是否拿稳、是否穿模
    -> 记录每一步的“执行前观测 obs_t”和“发出的动作 a_t”
    -> 筛出合格轨迹作为示范
    -> BC训练网络：看到obs_t时，尽量输出a_t
    -> 可继续用PPO训练，形成BC+PPO
```

因此，示范不一定来自真人，也可以来自经过验证的程序控制器、规划器或IK生成的参考。这是“用程序生成示范再模仿”，不等于做了人类视频学习。

教学版BC公式：

```text
theta* = argmin_theta sum_t ||pi_theta(obs_t) - a_demo_t||^2
```

这里theta是神经网络参数。实际工程在tanh之前的动作均值logit空间计算平方误差：将示范动作clip到[-0.995,0.995]后做arctanh，再与网络均值比较，见train_orca_matched.py中的fit_matched_bc。不是直接把指端位置误差拿来当BC损失。

S08采集了32次几何参考执行，其中30条通过标准；BC按完整轨迹划分22条训练、8条验证。网络学的是这批执行过程，而不只是最终一张手型。

只有一个IK终点姿态，不能直接声称有了覆盖各种状态的BC专家。需要动作时序、真实状态动作对应和足够的初态覆盖。仿真中验证过的示范也可能只在很窄范围有效；BC执行偏离示范后，仍可能出现误差累积。

## 13. DexMV与IK是不是二选一

不是。DexMV是从人类视频构建示范并用于机器人学习的一套流程；IK是把目标几何关系转换成关节配置的求解工具，层级不同。DexMV官方仓库本身就包含运动学重定向与示范生成，而且明确说明示范生成不止重定向，还涉及轨迹、时间对齐和动作空间匹配等步骤。见[DexMV官方仓库](https://github.com/yzqin/dexmv-sim)。

所以更合适的比较是以下两条完整路线，而不是抽象地说“DexMV和IK谁更强”：

| 比较项 | 人工几何目标 + IK + 物理验证 | DexMV示范目标 + 重定向/IK + 物理验证 |
|---|---|---|
| 谁决定大体抓法 | 工程人员写接触位置、方向、闭合规则 | 处理后的示范提供动作和手物关系，再做机器人适配 |
| 对简单已知物体 | 目标容易写清，可作为可解释基线 | 需要匹配的示范、坐标和物体尺度 |
| 对复杂动作 | 人工指定多阶段接触和时序的工作量可能增加 | 示范可提供候选接触关系和动作顺序，但不保证能迁移 |
| 主要误差 | 手工抓法假设、模型误差、局部求解失败 | 还会增加视觉重建、遮挡、尺度、跨手型和时间对齐误差 |
| 是否自动保证物理可行 | 否，摆得到不代表抓得稳 | 否，示范姿态也可能穿模或不适合机器人 |
| 是否可以生成BC样本 | 可以，经仿真执行和筛选后生成 | 可以，经适配、执行和筛选后生成 |
| 是否可以加残差PPO | 可以，把几何参考作为基础动作 | 可以，把示范参考作为基础动作 |
| 是否保证更高成功率 | 没有保证 | 没有保证，必须同任务同预算实测 |

这张表是方法层面的工程分析，不是新实验数据。S08只完成左边路线；S05/S06/S07使用过处理后人类/DexMV示范。用户新确认的纵向包覆DexMV参考还没有生成或训练，不能用S08的数字替它作证。

## 14. 你的研究里怎样表述才准确

```text
DexMV示范：提供大体抓法与手物关系
    -> 重定向/IK：翻译成Orca可以执行的参考动作
    -> 物理校正：排除明显不合理接触
    -> 残差PPO：每一步根据当前状态输出小修正
```

如果基础动作改为网络，也可以做：

```text
IK/示范生成数据 -> BC基础策略pi_base(obs)
最终关节目标 = pi_base(obs) + delta_q_PPO(obs)
```

这仍可形成残差结构，前提是执行时保留两个明确相加的分支，并统一输出单位、限幅与控制接口。建议先冻结基础网络再训练残差，便于解释谁贡献了什么；这只是可选设计，不是当前已完成的实现。

与之不同，“BC初始化一个网络，然后PPO继续更新这个网络”仍叫BC+PPO，执行时只有完整动作输出，不因用过IK或BC就自动成为残差架构。

结论：IK负责求角度，BC负责把示范变成策略网络，DexMV负责提供视频示范链路，PPO负责根据交互奖励学习。它们可以在同一条链路里合作，不是四个互相替代的东西。
