# S12 数据字段说明

本页针对 `artifacts/orca_benchmark_suite/S12/study_v2/`，帮助读取原始数据，不把尚未完成的实验记成完成。开发目录中的旧 V1 数据不纳入本轮结论。

快照时序注意：MuJoCo 的隐式积分先计算派生几何，再推进最后一次位置积分。因此保存的 `vertices` 对应末次位置积分前，而 `qpos` 对应积分后，相差一个物理小步（粗网格 0.2 ms，细网格 0.1 ms）。渲染使用保存的末次速度反向重建这一小步的位置，并逐帧验证与原始 `vertices` 一致；不改原数据或放宽容差。视频标签仍标控制周期结束时间，渲染元数据另记几何时间偏移。正式判分一直使用原有逐子步审计，没有因为视频重建而重算或变更。

## 1. 先看哪些文件

| 文件 | 含义 | 不应如何理解 |
|---|---|---|
| `protocol.json` | 开始测试前固定的配置、种子、预算与输入哈希 | 不是已完成证明 |
| `training/<方法_种子>/metrics.csv` | 训练过程中在 8 个开发初态上的阶段评估 | 不是最终保留集成功率 |
| `training/<方法_种子>/summary.json` | 训练末步与首末、最好阶段摘要 | 最好阶段不自动成为最终模型 |
| `evaluation_plan.json` | 所有训练完成后绑定预先指定的末步权重及 BC 起点 | 不是按测试结果挑选的权重 |
| `evaluation/<条件>/<策略>/episodes.json` | 每个独立测试回合的原始统计 | 一行不代表一个独立训练网络 |
| `evaluation/<条件>/<策略>/trajectory_<初态种子>.npz` | 该回合逐控制步状态、动作与物理审计 | 失败回合不能从分母删除 |
| `report/aggregate.csv` | 各方法和条件的汇总 | 不应忽略逐训练种子的差异 |
| `report/paired_differences.csv` | 同初态下的成功率差和区间 | 区间跨零时不能宣布稳定增益 |
| `report/failure_episodes.csv` | 掉落、接触违规、单元塌陷的逐例区分 | `alive=false` 不一定是掉落 |
| `report/verification.json` | 权重更新、动作映射、终止与材料有效性审计 | 数据完整通过不等于所有轨迹物理有效 |

未生成某个文件时，应检查实验是否尚未到对应阶段，不能补写一个“通过”结果。

## 2. 训练表怎么读

- `step`：所有并行环境累计的在线控制步。8 个环境分别走一步，合计 8 步。不是回合数、物理小步数或梯度更新次数。
- `elapsed_sec`：该训练程序记录的阶段耗时。不同来源的系统负载有差异，不能仅凭它给算法做严格速度排名。
- `success15`：固定开发初态上的严格通过比例；例如 0.875 代表 7/8，不是抓取持续了 87.5% 的时间。
- `hold_sec`：这些回合各自最长严格连续保持时间的平均值。它不等于所有回合最终时刻的保持时间。
- `return_mean`：整回合累计奖励均值。奖励增加不保证严格成功率增加。
- `strain_max`、`penetration_max`、`force_max`：该批开发回合中最大的局部应变、穿透和单接触法向力，不是均值。

`training_first_last.csv` 中，成功率和保持时间的 `best` 取最大值，应变的 `best` 取最小值。峰值阶段仅用于解释学习过程，正式评估仍固定 51200 步末点。

## 3. NPZ 是什么

NPZ 是一包带名称的 NumPy 数组，类似一个包含多张数字表的文件。正常完整回合有 480 行，每行对应 0.05 秒；提前失败的回合行数更少，原样保留。

| 字段 | 每行内容 | 单位与注意事项 |
|---|---|---|
| `time` | 当前控制周期结束时刻 | 秒；不是视频帧编号 |
| `obs` | 决策前的 93 维策略观察 | 与本行执行动作相对应，不是执行后的观察 |
| `action` | 网络输出，或参考回放转换后的归一化动作 | 17 维，无量纲，范围 [-1,1] |
| `video_base` | 残差模式执行时使用的基础参考角 | 17 维、弧度；绝对动作组为零 |
| `requested_residual` | 残差网络请求的修正 | 17 维、弧度；残差模式为 `0.08 * action` |
| `desired_ctrl` | 目标角，残差模式已叠加参考并应用关节限位 | 弧度；尚未应用每步变化限幅 |
| `ctrl` | 实际送入位置执行器的目标角 | 弧度；每 0.05 秒变化不超过 0.1 rad |
| `qpos`、`qvel` | 手与柔体节点的广义位置和速度 | 是控制周期末状态；各自由度单位随平移/转动而异 |
| `mocap`、`mocap_quat` | 理想手部位置控制目标和托台的位置/朝向 | 位置米，四元数表示朝向 |
| `vertices` | 柔体各节点的实际世界坐标 | 节点数随网格变化，每节点 xyz 三列，单位米 |
| `offset` | 该回合随机手位偏移 | 米；固定的 +3 mm z 基础偏移另在配置里，不能重复添加 |
| `loads` | 拇指及其余手指的指定正面接触载荷 | 牛顿；每个控制周期各物理小步总载荷的最小值，用于要求持续承载 |
| `forbidden_force_n` | 非指定接触的法向载荷合计峰值 | 牛顿；控制周期内取最大值 |
| `peak_force_n` | 最大单个接触的法向力 | 牛顿；不是全手合力，不是任一手指总载荷 |
| `support_force_n` | 托台支撑力峰值 | 牛顿；成功不能依赖未撤走的托台 |
| `max_principal_strain` | 所有单元、该控制周期内的最大局部主应变绝对幅值 | 无量纲；0.2 是 20%，不是整个物体统一缩小 20% |
| `min_volume_ratio` | 最小局部单元体积比 | 1 接近初始体积；<=0.05 触发终止，<=0 表示翻转 |
| `penetration_m` | 最大碰撞穿透 | 米；0.001 m 是 1 mm，与材料内部形变不是同一个量 |
| `hold_sec` | 截至当前时刻的严格连续保持时间 | 秒；一旦当前条件不合格便清零 |
| `success15` | 当前是否满足最终严格成功规则 | 最终统计读取该回合末行；曾有撤台后质量违规会永久失去资格 |
| `reward` | 本控制步奖励 | 对整列求和是回合累计奖励 |
| `alive` | 未达到环境终止条件 | 为 false 可能是掉落，也可能是局部体积严重塌缩 |

正式学习/评估轨迹中的状态快照主要是 float32，用于观察、分析和重建画面。物理工作进程内部使用的双精度完整积分状态通过 uint32 字传递，但并未把每一步的全部积分缓冲都写入这些 NPZ。因此仅用 `qpos/qvel` 不能承诺逐位续算同一条动力学轨迹；重新执行应使用配置、种子和原策略，并允许已记录的浮点运算差异。

残差的限制针对“请求修正量”。执行器存在速度限制和追踪误差，不能简单要求 `ctrl - video_base` 或实际 `qpos - video_base` 永远在 ±0.08 rad 内。

审计还区分三项残差幅度：网络请求、经过关节限位后的目标修正，以及在同一个上一控制目标下加入残差对本步执行命令的实际影响。最后一项只是一控制步的对照计算，不是把整个回合重新关掉残差得到的成功率。三项结果位于 `verification.json` 的残差任务条目；RMS 是均方根，描述典型幅度而非最大允许幅度。

### 策略观察的 93 列

下表使用 Python 切片，右端不包含在内。网络输入经过缩放，不应直接把整列当成原始物理单位。

| 切片 | 内容 |
|---|---|
| `0:17` | 归一化关节位置 |
| `17:34` | 关节速度乘 0.1 后截断到 [-5,5] |
| `34:51` | 归一化执行目标角 |
| `51:68` | 上一次归一化动作 |
| `68:71` | 物体相对手部的位置偏差乘 20 |
| `71:74` | 物体中心的有限差分速度，截断到 [-2,2] |
| `74:77` | 物体世界坐标包围范围 xyz 尺寸乘 20 |
| `77:82` | 五指指定接触载荷的指数平滑值乘 0.2 |
| `82:87` | 上述平滑载荷的变化乘 0.2 |
| `87:90` | 整回合、撤台、抬升三项归一化相位 |
| `90:93` | 手部坐标系内的重力方向 |

BC 起点只使用 `87:90`，PPO 后全部列可以影响动作。价值网络再追加 17 个执行器力和 3 个内部材料审计值，共 113 列；执行动作不需要价值网络输出。

## 4. 回合统计与失败分类

`success15` 是严格通过；`physical_success15` 仍要求拇指与另一手指的指定正面持续承载、撤支撑和抬升，只不施加严格形变/穿透/峰值力/非指定接触质量门槛及历史违规记忆。它不是单纯“未掉落”，二者不能互换。`best_hold_sec` 是最大严格连续保持，`physical_best_hold_sec` 是最大宽松保持；最终成功仍要求末段持续满足对应条件。

`max_principal_strain` 和 `forbidden_force_max_n` 覆盖整个回合。原始 `post_release_strain_max` 从开始撤台的 5.0 秒起取峰值；失败诊断表的 `post_release_strain_max` 从撤台完成的 5.5 秒起取峰值，与严格违规记忆的起点一致。阅读时注意所在文件，不把两个时间窗混在一起。

`failure_episodes.csv` 中违规控制区间数是“有至少一个违规物理小步的 50 ms 区间”数量。乘以 0.05 不是精确的物理接触持续时长，因为原始审计聚合了区间内的小步。

`first_*_sec` 也是首次检测到异常的控制区间终点，不是精确到 0.2 ms 的物理事件时刻。例如记录 3.85 秒表示异常在该控制区间内已经发生，短视频保存到对应记录帧。

单元翻转不能解释成真实物体破裂。发生此类异常时，仍按失败保留分母，另报告模型有效性失败比例；若需要解释真实材料行为，必须进一步更换/标定材料离散与验证，而不是只放宽成功条件。

## 5. 视频与统计的关系

短视频到拿稳四秒就停，仅用于直观展示；是否保持 15 秒由同一条完整回合的数据判断。每个视频需记录任务、方法、训练种子、测试初态、是否成功和原始 NPZ 路径。

一个漂亮视频不是成功率证据。主要对比应使用同一个预先确定的初态，失败也保留；补充挑选的成功例必须明确写为成功示例，不能替代全部初态的统计。
