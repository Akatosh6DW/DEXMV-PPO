# DEXMV-PPO 项目交接简介

> 更新：2026-10-18。写给接手的同学：先读这一份了解全貌，再按第 10 节的阅读路线深入。
> 文中数字均摘自仓库内已有报告，未重新计算；不同轮次的任务和判据不同，**跨行数字不能直接排名**。

## 0. 一句话

先把**人类视频里的抓取动作**（经 DexMV 工具处理）转换成仿真机械手 **Orca 右手**能执行的一段"参考动作"，再用 **PPO 强化学习**在 MuJoCo 仿真里修正它，让手抓住物体，并在撤掉支撑后稳定保持 30 秒。
研究的核心问题是：**视频先验以什么方式接入 PPO 最有效？** 一种是"BC 先模仿、再 PPO"，另一种是"参考动作 + PPO 残差修正"。

---

## 1. 任务目标

| 项目 | 内容 |
|---|---|
| 研究问题 | 视频先验能否让 PPO 学得更快、更稳？两种接入方式（BC 后 PPO、参考加残差 PPO）各自的效果如何？ |
| 最初设想 | "大的动作由视频决定，细节由 PPO 微调"，对应执行时显式相加的**残差架构** |
| 机械手 | Orca 右手，17 个执行器（1 个腕关节加 16 个手指关节）。腕座固定，没有机械臂 |
| 物体 | 与视频同源的 53 mm 方块（S02 至 S05），以及直径 53 mm、高 53 mm 的圆柱（圆柱 S02、S06 至 S09），质量均为 35 g |
| 一个回合 | 共 40 s。物体先由托板（S09 改为吊绳）支撑，约 3 s 时撤掉，之后只能靠手拿住 |
| 成功标准 | 撤掉支撑后**连续 30 s 严格合格**，且第 40 s 时仍然合格。"严格合格"指：拇指和至少一根对向手指的指腹承力都大于 0.02 N，没有非手部支撑，穿透不超过 3 mm，高度下降小于 15 mm。S05 以后才要求"指腹"，S02 至 S04 的判据较宽 |
| 不在范围内 | 真机部署、运行时读摄像头的视觉控制、开瓶盖（做过原型，已存档） |

## 4. 实现方案（整体链路）

```text
人类视频：HIC 第 20 段（单手移动方块）/ DexMV 番茄罐序列 96（圆柱）
  │  直接使用数据集作者已发布的三维手物跟踪结果，没有重新做 RGB 识别
  ▼
DexMV 重定向：人手 21 个关键点 → Adroit 手（30 维）→ 正运动学得到"指尖相对物体"的轨迹
  ▼
Orca 逆运动学：用 SciPy least_squares（TRF 算法）同时拟合指尖位置、指腹朝向，并惩罚穿透
  ▼
仿真校正：在小范围内搜索关节偏置，确认这段动作在仿真里真能抓住
  │  → 参考轨迹 q_ref(t)，保存为 reference.npz
  ├──► 在不同初态下回放参考，筛选成功回合 → BC 示范（trajectories.npz：obs / action / active）
  ▼
四种方法在同一个仿真任务里训练或回放（见第 5 节）
  ▼
在独立测试初态上评估 → 统计（种子均值、bootstrap 区间、Holm 校正）→ 原生物理回放核验 → 手心视角视频
```

有三点容易误解：

- 视频**只在离线阶段使用**。运行时，策略看到的是仿真状态（关节、物体位姿、模拟触觉），不是相机画面。
- 整个项目只有**一段源视频对应一个物体**。所谓"40 条示范"，是同一段视频在不同初态下的仿真回放，不是 40 段视频。
- S08 的参考是纯几何求解得到的，没有用视频。

## 5. 算法设计

### 5.1 四种对比方法

| 方法（代码中的名字） | 训练方式 | 执行时每一步的动作 |
|---|---|---|
| 纯 PPO（`ppo`） | 从随机网络开始在仿真中试错 | `q = 映射到关节范围(π(o))` |
| BC 后 PPO（`guided`） | 先用示范做行为克隆（BC），再接 PPO | 同上，由一个网络输出完整动作 |
| 参考加残差 PPO（`residual`） | 只学习有界的修正量 | `q = clip(q_ref(t) + 0.08·clip(π(o), −1, 1), 关节限位)` |
| 参考回放（`reference`，对照组） | 不训练 | `q = q_ref(t)` |

- 四组共用同一条限速规则：每 50 ms 每个关节最多变化 0.1 rad。
- 残差每个关节的修正上限是 0.08 rad（约 4.6°）。把修正置零，就退回到参考回放。
- 参考回放组必须保留。只有它能区分"参考本来就会抓"和"PPO 确实补上了什么"。
- 合成代码见 [orca_residual_controls.py](../scripts/orca_residual_controls.py) 中的 `compose()`。

### 5.2 网络与 PPO 设置（以 S09 为例）

- **实现**：直接使用 Brax 的 PPO，没有自己写算法。actor 和 critic 都是 128×128 的 MLP，采用非对称结构：actor 输入 123 维，critic 输入 140 维（多出 17 维执行器力）。
- **actor 的观测**：
  - 手：关节位置与速度、上一步的目标和动作
  - 物体与指尖：物体位置、速度、轴向，5 个指尖相对物体的位置
  - 时间：释放阶段和回合时间
  - 参考：当前参考动作（只有残差组填值，其他组填零）
  - 触觉：模拟信号，带噪声和一个控制周期的延迟
  - 各维度的切片见 [S09 文件与复现说明](experiments/S09/文件与复现说明.md)。
- **动作和时序**：17 维动作，每 50 ms 输出一次；物理子步是 5 ms，每个动作对应 10 个子步。
- **训练预算**：163840 次在线交互（32 个并行环境，unroll 长度 20，4 个 minibatch × 4 轮更新），γ = 0.99，GAE λ = 0.95，裁剪 ε = 0.3。
- **学习率和探索**：纯 PPO 和残差组用 3e-4，BC 后 PPO 用 3e-5；初始动作标准差都是 0.3。
- **BC 损失**：`L = mean[(μθ(o) − atanh(clip(a_demo, ±0.995)))²]`，Adam 学习率 1e-3，每批 256 个样本，接近阶段和保持阶段各占一半，共 4000 次更新。
- **奖励（S09-R0）**：`r = 0.05 × (15·严格抓稳 − 50·掉落终止 + 2·对向接触覆盖 + 2·释放前接近程度)`。奖励中**没有**"动作像不像视频"的项。

### 5.3 S09 的特殊设计

- **悬吊**：圆柱用理想质心弹性绳吊起，3 s 时释放；初始朝向在三维旋转空间（SO(3)）中均匀随机，环境实现见 [s09_suspension.py](../scripts/s09_suspension.py)。
- **参考库**：共 6 个朝向模板，每回合按圆柱的初始轴选最近的一个。
- **三指参考**：参考只拟合拇指、食指、中指（共 11 个执行器）；无名指和小指的参考为 0，所以实际上是三指抓。
- **BC 修复（10-15）**：
  - BC 的输入增加初始模板的 one-hot 编码。
  - BC 阶段只看"模板 + 时间"两类输入：其余输入置零，对应的第一层权重也清零；训练 40000 次更新。
  - 接上 PPO 后恢复全部输入，标准差改为 0.03，学习率 3e-5。

## 6. 实验方法（如何保证结果可信）

1. **先冻结协议**：训练前把模型、参考、示范、奖励、超参数的哈希写入 `protocol.json`，冻结后不再修改。
2. **种子分离**：开发集（用于调参）、BC 训练和验证、最终测试分别使用不同的初态种子。正式评估之前不看测试成绩。
3. **配对测试**：所有方法在同一批初态上测试，可以逐例比较谁成功、谁失败。
4. **多个训练种子**：每种方法训练 3 到 10 个种子，报告均值、种子标准差和分层 bootstrap 95% 区间；多重比较用 Holm 校正。
5. **固定选模**：一律使用最后一个检查点，不挑测试成绩最好的中间点。
6. **对照与消融**：
   - 参考回放（零修正）、仅 BC
   - 不同参考：未校正参考、线性合拢参考
   - 残差增益设为 0 / 0.5 / 1
   - 扰动条件：位置、朝向、摩擦、质量、外力
7. **物理审计**：在每个 5 ms 子步检查接触部位、承力和穿透；保存的轨迹用原生 MuJoCo 重新回放核验；视频同时导出碰撞几何版和 STL 外观版。
8. **保留失败结果**：失败和退化的结果全部保留。奖励迭代另起编号（R1、R2…），不混进正式表。

## 7. 实验历程与主要结果

| 时间（2026） | 阶段 | 做了什么 | 关键结果 |
|---|---|---|---|
| 05-12 至 05-19 | 链路打通 | DexMV → Aero 手（6 个执行器）→ 残差 PPO；随后接入 17 个执行器的 Orca 手 | 只证明链路能跑通 |
| 10-02 | Aero 手 HIC20 方块 | 视频先验 BC 加残差 PPO | 16/16 次测试保持超过 20 s（平均 38.1 s），但不带先验的对照在开发种子上更好 |
| 10-02 至 10-03 | Orca F01、R05 至 R08 | 36 mm 方块：BC 加 PPO 对比纯 PPO；方块、球体、长方体三组对照 | 引导组学习曲线面积（AUC）更大，但最终成功率不占优；球体三组全部失败 |
| 10-04 至 10-05 | 引导复核、长训练、碰撞重构 | 基于 STL 重新拟合碰撞体，改用与视频同源的 53 mm 方块 | 残差短训能提升先验，长训会退化（58% 降到 27.5%）；HIC53 残差两个种子分别 60/64、64/64 |
| 10-06 | 正式 F01（方块） | 80 次训练、513 项评估 | 任务太容易：纯 PPO 约 100%，残差约 94% |
| 10-07 | M01 张开起手 | 让手先张开，任务变难 | 纯 PPO 1.6%，BC 加 PPO 54.7%，残差 72.9%（参考回放 65.6%） |
| 10-08 | **S02 方块基准** | 10 个种子、5 种方法、6 个条件、77600 个回合 | 正常条件清洁成功率：纯 PPO 29.3%，仅 BC 51.6%，BC 加 PPO 68.9%，参考 68.0%，残差 69.8%。残差对纯 PPO 的 Holm 校正 p = 0.053，未达显著 |
| 10-09 | S03（中途停止）、**S04 新初态复测** | 用调优后的配方，在 100 个新初态上测试 | 纯 PPO 31.3%，仅 BC 63.5%，BC 加 PPO 84.0%，参考 66.0%，残差 85.1%。残差比纯 PPO 高 53.8 个百分点，95% 区间 [38.8, 68.2]，p = 0.004；BC 加 PPO 比纯 PPO 高 52.7 个百分点，p = 0.006。残差组的种子标准差最小（5.9，BC 加 PPO 为 23.8） |
| 10-10 | 圆柱 S02 | 物体换成圆柱，示范换成 DexMV 番茄罐 | 纯 PPO 40.6%，残差 33.4%，参考 18.5%，BC 加 PPO 崩溃到 0% |
| 10-12 | S05 至 S08 | 判据改为指腹接触；圆柱三指抓；掌面包覆 | S07：仅 BC 70.3%，残差 67.7%，参考 59.4%，BC 加 PPO 1.6%，纯 PPO 0%。S08：参考 96.9%，BC 加 PPO 96.4%，仅 BC 94.3%，残差 93.8%，纯 PPO 0% |
| 10-15 | **S09 多朝向悬吊圆柱** | 4 组方法，各 3 个种子，圆柱初始朝向随机 | 随机朝向下：参考 47.7%，残差 37.2%，纯 PPO 23.4%，BC 加 PPO 4.2% |
| 10-15 | S09 BC 修复 | 加入模板条件和输入课程 | 在 128 个新初态上，BC 加 PPO 从 5.2% 提升到 35.4%（参考回放 40.6%） |
| 10-18（进行中） | S09 PPO 增益迭代 E01 至 E48 | 目标：让 PPO 在自己的起点上继续提高 | 只有开发集结果：BC 加 PPO 三个种子长训后比 BC 起点高 3.1 个百分点（38.0% 到 41.1%）；残差最好 48.4%，零修正起点 45.3%，提升很弱 |

**目前可以下的结论：**

1. **链路已完整打通**：视频 → 重定向和 IK → 参考 → BC 或残差 → PPO → 严格评估，所有环节都可以追溯。
2. **方块任务上融合有明显收益**：在与视频匹配的方块任务、有限训练预算下，两种融合方法都大幅优于纯 PPO（S04 约高 53 个百分点，p < 0.01），其中残差组训练最稳定。
3. **收益依赖任务**：在圆柱和多朝向任务中，主要能力来自参考本身，PPO 修正经常加不上去，甚至会变差；BC 后 PPO 容易把示范学到的抓法忘掉。
4. **参考质量决定上限**：校正、时序和朝向覆盖都很关键。消融实验显示，未校正的参考、只有起点终点的线性参考，成绩都会明显下降。

## 9. 待完善的点

### 工程与交接（建议优先处理）

1. **代码几乎没有进版本管理**：主仓库只跟踪了 8 个文件，`scripts/` 和 `docs/` 全部未提交；`Aero-Hand` 子模块里的 Orca 环境（`orca_hand/`）和训练脚本的修改也没有提交。一旦换机器或误删，代码会全部丢失。
   - 建议：尽快提交代码和文档。45 GB 的 `artifacts/` 放到外部存储，仓库里只保留小文件，如参考 npz、`protocol.json` 和报告。
2. **代码组织松散**：
   - `scripts/` 平铺了约 460 个文件，每轮实验都复制一套环境、运行和分析脚本。
   - 环境靠很长的继承链复用（`orca_benchmark_env → orca_residual_env → orca_refit_env → …`），而且字段名沿用了 `cube_*`、`video_base`，做圆柱任务时也叫 cube。
   - 建议：把环境、残差合成、评估和统计抽成公共包，再按实验分目录。
3. **没有一键复现入口**：各轮实验的命令分散在各自的文档里。建议为当前主线（S09）写一个总的 README 或 Makefile。

### 研究方向

4. **参考覆盖不足**：S09 只有 6 个模板，竖直方向几乎全部失败；无名指和小指的参考为 0。可以考虑增加模板、做随朝向连续变化的条件参考，以及五指参考。
5. **视频来源单一**：只用了 HIC20 和 DexMV 序列 96，圆柱示范和原始 RGB 视频的对应关系也没有核实。需要引入多段独立视频，并按视频划分训练集和测试集，才能讨论泛化。
6. **PPO 在先验之上的净增益不稳定**：残差经常不如单纯的参考回放，BC 加 PPO 会遗忘。E 系列中有弱的正结果，例如快 critic 加慢 actor、弱 KL 约束、critic 预训练，需要在保留测试集上确认。
7. **闭环反馈的作用没有被证实**：缺少"实时残差"和"固定修正量回放"的配对实验，所以还不能说提升来自实时纠错。
8. **离真机还很远**：
   - 质量和摩擦是假设值，手指自碰撞没有完整启用。
   - 接触力峰值可能达到 100 至 200 N，成功判据并不约束它。
   - 物体位姿来自仿真真值，真机需要状态估计、参数标定和安全限幅。

**术语速查**：

| 术语 | 含义 |
|---|---|
| BC（行为克隆） | 照着示范的"状态 → 动作"做监督学习 |
| PPO | 根据仿真里试错得到的奖励，小步更新策略的强化学习算法 |
| 残差 | 执行时加在参考动作上的有界修正量 |
| IK（逆运动学） | 已知指尖要到哪里，反过来求关节角 |
| 重定向 | 把人手的动作转换成另一种手的动作 |
| 种子 | 一次独立训练或一个测试初态的编号 |
| 检查点 | 训练到某一步时保存的网络参数 |
