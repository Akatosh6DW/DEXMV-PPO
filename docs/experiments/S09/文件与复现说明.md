# S09文件、环境和复现说明

## 环境

在主工程`/home/ll/SRTP/DEXMV-PPO`执行，使用已有的`aero_rl`环境：

```bash
conda activate aero_rl
```

本轮把已有DexMV示范作为离线输入，不需要把旧DexMV学习库安装进aero_rl。MuJoCo物理在CPU原生回调中计算，JAX/Brax策略与优化使用GPU。不能因为看到GPU占用低就断言训练没有运行，也不能把容器无法访问显卡误当成主机没有驱动。

软件版本已写入`artifacts/orca_benchmark_suite/S09/protocol.json`，没有为本轮修改驱动。CPU单测通过不替代GPU训练验证；本轮训练日志记录了实际backend。

## 文件分别干什么

| 位置（相对S09结果根目录） | 内容 | 不应误解为 |
|---|---|---|
| `inputs/model.xml` | 悬吊圆柱和Orca物理场景，引用原工程网格资产 | 已包含所有资产的独立场景包 |
| `inputs/reference.npz` | 6个朝向模板、控制时序和物体姿态 | 一个端到端视觉网络 |
| `demonstrations/trajectories.npz` | 56条成功示范的观测、动作及活动掩码，BC在内部再分训练/验证 | 全部128次采集都成功 |
| `train/*/step_000163840/params.pkl` | 三种学习方法各3个种子的末步策略/价值网络参数 | 输入RGB即可部署的完整机器人系统 |
| `train/*/metrics.csv` | 训练前及每40960步的8例开发监测 | 最终保留测试 |
| `train/*/ppo_metrics.jsonl` | 优化器更新过程中记录的PPO指标 | 逐回合成功率或每个真实动作的日志 |
| `eval/*/*/step_000000000/episodes.json` | 全部保留测试的逐回合结果 | 全部回合的逐帧完整状态 |
| `initial_states.npz` | 每个测试初态的qpos和种子 | 每一步的完整轨迹 |
| `preview_trajectories.npz` | 固定早期案例加成功/失败预览，含实际动作和物理状态 | 所有测试回合都保存了逐帧轨迹 |
| `native_replay_audit.json` | 已保存预览的原生回放核验 | 换物理引擎或实物验证 |
| `report/episodes.csv` | 2560回合汇总原始记录，保留方法/种子/方向 | 2560次独立模型训练 |

`.npz`是多个数值数组的压缩容器，不是视频；`.pkl`是Python序列化参数，只读取可信的本工程文件；`.mp4`才是可直接观看的视频。参考轨迹和网络权重作用不同，残差策略运行时两者都要，BC后PPO不再显式加参考。

结果根目录是`artifacts/orca_benchmark_suite/S09/`。交付文件夹只汇总报告、数据、说明、源码阅读副本和视频，不复制权重及全量训练数据；完整文件仍在原工程，未删除。

## 如何重新生成统计与视频

仅在完整评估完成后执行；缺项会报错，不会拿部分数据发布完整表格：

```bash
python scripts/analyze_s09_study.py
python scripts/summarize_s09_diagnostics.py
python scripts/export_s09_showcase.py
python scripts/package_s09_report.py
```

重新统计不是重新训练。不要删除原输出目录，不要重复freeze；冻结文件用于核对源文件、场景、数据与权重是否还是同一版本。队列只跳过已核实完成的任务，碰到未完成输出会拒绝覆盖，需先查日志。

如果确实需要新增测试，指定全新的输出路径和种子，沿用同一个`inputs`和对应末步`params.pkl`。不要覆盖正式测试目录，也不要把新增调参成绩混入冻结R0。

## 单元测试

```bash
JAX_PLATFORMS=cpu OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
PYTHONPATH=scripts:Aero-Hand/sim_rl/mujoco_playground \
python -m unittest test_s09_suspension test_s09_env test_s09_reward test_s09_audit
```

当前共12项测试。沙箱中的JAX CUDA插件可能打印无设备提示，但上述命令明确选择CPU；看最终unittest结果判断单测是否通过。实际训练命令不能设置`JAX_PLATFORMS=cpu`。

## 复现边界

原机种子、初始化、源码快照、哈希与配置均保留，但不承诺换GPU/软件版本后接触轨迹逐位相同。参考控制的归一化往返会引入约1e-7 rad量级舍入，失败接触可能放大微小差异，已有专门诊断记录。

原生回放核验验证的是“代码确实按记录的动作产生这些状态”，不是证明碰撞代理形状、摩擦和传感器完全符合实物。仍需物理步长敏感性、摩擦/质量扰动及真实传感器标定，才能进一步讨论硬件迁移。

## 策略接口

三种学习方法均为17维输出，控制周期50 ms。必须匹配对应的动作解释：纯PPO/BC后PPO输出映射到关节范围；残差输出先乘0.08 rad再加参考，不能拿残差权重当完整关节目标执行。

为了统一追溯，评估入口对所有方法都校验`inputs/reference.npz`的哈希，但纯PPO/BC后PPO并不把其中的参考动作送入控制合成。场景内部的`cube`、`cube_freejoint`是沿用的接口名称，本轮物体几何类型已是圆柱，不是名字写cube就仍在抓方块。
