# E82：接近六专家容量的单网络BC后PPO

## 具体假说

E78真实末步在256个新初态优于原BC和同在线预算单网络，但actor有六倍参数。因而收益可能来自容量或条件表示能力，不必然是按朝向路由解决了梯度冲突。E82只改变完整动作网络容量，保留原123维输入、共享128x128 critic、奖励R0、物理、随机朝向和成功门槛。

源为E30的step_000491520（源训练路径累计655360在线步），与E77/E78起点相同。不是重新从原始视频或从零BC训练，也不是反馈BC数据干预。最终依旧由单一可训练网络给出17维完整动作，没有基础参考与修正相加。

## 初始化与调试记录

参考函数保持扩展的思想：[Net2Net，Chen等，ICLR 2016](https://research.google/pubs/net2net-accelerating-learning-via-knowledge-transfer/)。本轮实际采用零输出扩展，不冒称完整复现Net2Wider。

最初实现复制神经元、分摊输出权重的Net2Wider转换，普通随机复制和二进制次数复制均在CPU检查中超过事先设定的1e-5 logits误差；前者64随机输入最大4.4823e-5，2396个原轨迹状态最大2.8014e-5（动作1.4052e-5），后者随机输入最大3.3617e-5。设置highest矩阵精度未解决。没有生成这些候选的训练权重，没有放宽门槛，也不把它们当性能实验。

实际方案：128x128旧隐藏层扩至397x397，保留左上旧子网络；新增单元有随机输入连接，但通向旧路径和最终输出的连接初始为0。训练后允许这些连接更新。这是单个稠密网络，不是运行时调用两个网络相加的残差结构。固定扩展随机种子19411，不根据抓取结果挑选。

- 原actor 36770个参数，六专家共220620，扩宽actor 220766；相对六专家多146个（0.066%），是近似等参数量而不是精确相等。
- critic及归一化原样保留，不重新拟合示范，额外在线交互为0。
- 转换后64个随机输入和2396个保存状态的全部logits误差均0；这里只是已检查输入的函数核验，不保证所有GPU接触轨迹逐位相同。
- 4项针对测试通过：源参数不变、函数保持、不允许缩小、参数量，以及新增输出连接可获得非零梯度（合计4个测试方法）。
- 转换输出`artifacts/orca_benchmark_suite/S09/bc_repair/ppo_improvement_20261018/wide_inputs/E30_zero_output/`，记录来源与哈希。

源SHA256：`4e54df8821b2e4c6bcfc2e7a7dbab0194cdba49983f3112d380461b4cfe51fb9`；转换权重SHA256：`2c2eebad8ceeb5d8b3c852331d87c55c130d38adfd8d7f285b19b868cf2877a3`。

## 预定训练与验收

先CPU2560步、8个开发初态预检；审计起末两步模型动作与原生物理，检查新连接确实更新。通过后从未训练的转换副本开始正式163840步，不用预检权重。与E77及E46的相同步数比较，分别在0、81920、163840评估64开发初态130000--130063，不使用170000确认集调参。

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 XLA_PYTHON_CLIENT_PREALLOCATE=false JAX_ENABLE_COMPILATION_CACHE=false \
/home/ll/miniconda3/envs/aero_rl/bin/python scripts/run_s09_wide_actor.py \
 --input artifacts/orca_benchmark_suite/S09/inputs \
 --output artifacts/orca_benchmark_suite/S09/bc_repair/ppo_improvement_20261018/E82_bc_wide_actor \
 --method guided \
 --checkpoint artifacts/orca_benchmark_suite/S09/bc_repair/ppo_improvement_20261018/wide_inputs/E30_zero_output/params.pkl \
 --seed 14122 --std .03 --learning-rate .000003 --critic-lr .0003 \
 --steps 163840 --evals 3 --eval-count 64 --eval-start 130000
```

预检把输出改为`smoke_wide_actor_20261019`，步数2560、eval-count8，并加`--allow-cpu`及`JAX_PLATFORMS=cpu`。审计入口`audit_s09_wide_actor.py --run <目录> --step <步数>`。

结果必须报告success与hold的first/last/max/best_step，相对自身起点和相同预算对照的新增/丢失、六朝向表现、穿透/载荷。初始成功如不一致，要如实注明，不能归咎训练。仅有更多参数并不保证有效容量被利用，另检查新增连接更新量。

若扩宽单网络同样提高，则“路由独有优势”的解释减弱；若没有提高，也不能用一次初始化证明所有大网络无效。单训练来源、开发初态复用和初始化差异均为限制。无论正负都保存，不改变严格30秒验收标准。

## CPU预检结果

2560步预检已完成：success first/last/max均4/8，best_step=0；平均合格20.531降到20.438秒。末步最大穿透1.800mm、峰值24.761N、禁止接触及释放后绳力0。新增第二隐藏层输入行变化L2范数0.0051173，新增输出行0.0017867，确认新增容量没有被全部冻结。

初始保存预览通过普通动作/物理审计；末步首次大批量动作重算最大差1.3411e-5，高于原1e-5门槛，没有将此记为通过。审计改为与评估一致的逐帧scan(vmap(actor))并补齐同8例batch后，末步动作误差为0，完整原生物理回放也通过，容差未改变。该问题只涉及审计推理形状，不改权重、训练或原始轨迹。对应形状和批量上限检查加入测试。

正式E82随后按上方命令执行。147项完整S09测试通过，新增匹配形状测试另行执行；最终报告以完成的summary和审计为准，不把预检4/8当正式成绩。

## E82正式完成

163840步完成且三时点评估预览均通过动作/原生物理审计，逐帧动作误差0。success first=29/64（45.3125%）、last=29/64、max=30/64（46.875%）、best_step=81920；平均合格first=21.110、last=20.261、max=21.110秒，best_step=0。末步最大穿透3.677mm、峰值54.883N，禁止接触与绳力0。最大穿透包含失败，不改变原成功门槛。

相对自身阶段起点新增3、丢失3；相对同预算原单网络27/64新增2、丢失0；相对六专家35/64新增1、丢失7。三组零步成功标签相同，但若干连续物理量不同，统计已保留差异计数。新增连接确实训练：新第一层列29590个参数变化、新第二层行106792个、新输出行9146个，不能把无收益解释为新容量完全没有梯度。

这轮容量扩展缓解了一点相对小网络的退化，但没有超过自身阶段起点，也没有达到六专家表现；不支持“只要参数多就自动有同样收益”。单初始化/开发集结果仍不能唯一证明路由的因果作用。暂不对E82盲目延长，下一轮改动类型为PPO可训练参数保护：先按开发记录保留不同阶段强项，再将保护/不保护作为单变量训练对照。
