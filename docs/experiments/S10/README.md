# S10：整手先对准，再抓取随机朝向圆柱

本实验回应“让手腕/整手转过去，尽量使用同一种相对抓法”的要求。与 S09 固定基座实验分开保存，不改写旧结果。

先读[通俗版：从头理解整手对准实验](从头理解整手对准实验.md)和[结论与分析](结论与分析.md)。最终结果和逐例数据放在[数据报告目录](../../../artifacts/orca_benchmark_suite/S10/report/)，主要视频集中在[视频目录](../../../artifacts/orca_benchmark_suite/S10/videos/目录.md)。

## 当前状态

S10冻结实验已完成：9次163840步训练；14个策略/来源组合各测试128个共同初态，共1792条记录；另有4种几何控制共512条记录。重复的严格零残差质量核验不算新的独立样本。所有原始文件位于 `artifacts/orca_benchmark_suite/S10/`。

原标准三来源平均：从零手指PPO 1.56%、BC后PPO 93.49%、参考加残差PPO 91.41%；严格零修正参考91.41%，仅BC诊断93.75%。加入接近阶段穿透检查后，从零PPO与BC后PPO分别为1.30%和93.23%，其余不变。整手移动对准可行，但没有证据说明本轮PPO相对各自参考/BC起点有稳定净收益。

14个手心视频、3张图表、逐例CSV和配对统计均已生成。核验入口是 `scripts/verify_s10_delivery.py`，证据保存在 `report/completion_audit.json`；覆盖源码及输入哈希、末步权重、共同初态、完整视频解码和11项单元测试。物理独立回放只覆盖明确记录的保存预览，不冒称所有测试轨迹都独立重放。

## 核心方案

1. 使用已有 DexMV 示范经过 Orca 重定向、接触校正后的参考库。本轮不宣称重新从原始视频提取。
2. 在开发集选择一套参考抓法和一种对准规则。圆柱无纹理，绕自身轴旋转、轴方向反转可视为几何对称。
3. 根据开局测得的物体位姿，把参考中的“物体与整手的相对位置/朝向”搬到当前物体处。
4. 从统一的远离物体的起点出发，用连续位姿目标驱动真实六自由度动态手基座。只修改控制目标，不在每一步直接改写手或圆柱的物理位置。
5. 比较同一对准控制下的参考回放、纯 PPO、BC 后 PPO、视频参考加残差 PPO；仅 BC 另作诊断。额外检查不对准和直接预摆位，区分姿态归一化、接近路径及学习带来的效果。

公式：`世界中的目标手位姿 = 世界中的物体位姿 × 示范中物体到手的相对位姿`。代码还利用圆柱对称性消除无意义的轴向转动，不根据测试结果挑选姿态。

## 仿真边界

- 整手基座新增 freejoint，即三个平移加三个旋转自由度；保留 17 个原手部执行器。
- 无碰撞的 mocap 目标通过 MuJoCo 柔性 weld 等式约束驱动动态基座。这是理想化笛卡尔位姿控制器，不是已经建模的机械臂，没有证明机械臂关节可达性、限力或实机安全。
- 原固定安装架没有质量；新增自由基座使用0.1千克质量和0.001 kg·m²各轴惯量作为虚拟位姿执行平台参数，不代表测得的真实机械臂惯性。
- weld 只连接目标与手，不连接物体。圆柱仍通过接触、摩擦受力，释放后没有绳索支撑。
- 任务是接近初始悬挂的圆柱、撤支撑后原位抓持；不是从桌面拾起、抬升或搬运。整手到达后保持目标基座位姿，不额外训练搬运轨迹。
- 目标位置用平滑插值、朝向用旋转向量插值。起点相同，2 秒完成整手接近，随后参考闭合；所有新对照均 5 秒撤支撑，42 秒结束。连续合格保持 30 秒和结束时仍合格不变。
- 为留出整手转动空间，圆柱和参考工作空间整体抬高 25 厘米；物体位置扰动仍为正负 2 毫米。不能把 S10 成绩与原 S09 直接相减，作为严格的单变量优势。
- 圆柱仍直径 53 毫米、高 53 毫米、质量 35 克；接触须拇指与至少一根对向手指的合格掌侧面承力；初始穿透不超过 1 毫米，释放后不超过 3 毫米，不能依赖非法支撑。
- 重力方向不随坐标归一化而消失。PPO 观测保留手坐标中的重力方向，便于学习朝向变化后的受力修正。
- 当前物体初始位姿直接读取仿真真值，不是摄像头在线估计；正负2毫米是物体位置变化，不是传感误差测试。相机标定、遮挡、识别误差和机械臂定位误差都尚未验证。
- “从零 PPO”仅指手指策略网络从零训练。所有组共享由参考相对位姿确定的对准器，因此它并非整个系统无视频先验的纯 RL；本对比隔离的是手指学习方式。
- 共同对准器也有开发搜索成本；BC有示范收集和监督学习成本。相同163840在线步数不等于相同总数据、算力或调参成本，不能据此宣称所有意义下训练效率都公平。

实现依据：[MuJoCo mocap 与动态物体约束建模](https://mujoco.readthedocs.io/en/stable/modeling.html#mocap-bodies)。

## 开发记录

### D01：真实运动短探测

命令：`python scripts/probe_s10_alignment.py --name D01_minimal_t0 --count 8 --seconds 12`。

沿用参考 0，最小旋转对准。8 个开发案例中 7 个保持完整的 7 秒释放后窗口，平均最好连续保持 6.3375 秒。由于回合只跑 12 秒，严格 30 秒成功数为零，不能误报为 87.5% 最终成功率。下一步选择环境/几何类型变更：比较参考模板与朝向规则，保持奖励和手部控制不变。

### D02：短候选筛选后长验证

六个参考模板、两种轴对准规则，各 8 个短开发案例；短测前二再跑 16 个全长开发案例。参考 1 最小旋转 50%，参考 3 重力方向规则 25%。此处暴露短时稳定不等于长时保持。下一步仍为环境/几何类型变更：D03 扩大到完整 42 秒候选验证，不仅保留短测前二。

### D03：全长筛选完成

12 个候选，各自使用相同的 16 个长时开发初态。最后选择参考 0、最小轴对准、绕圆柱轴额外旋转 -0.5 弧度，开发集 16/16 成功、平均连续抓持 37 秒、全部案例接触力峰值最大约 6.11 N。参考 0 不加轴向旋转同样 16/16，但峰值最大约 13.82 N；按预先写入脚本的成功率、保持时长、峰值力排序选前者。开发结果不作为正式性能。

`inputs/selection.json` 是 D02 旧候选，保留用于追溯；正式实验使用 `inputs/selection_v2.json`，已绑定模型和参考哈希。

### D04：GPU 接口短训练

这是旧 D02 候选的接口烟测，不是最终方案效果：2560 次在线交互，残差严格成功率 first=75%、last=50%、max=75%、best_step=0，8 个开发初态。最大释放后穿透约 1.17 毫米，无非法支撑或释放后绳力。它说明接口可运行，也提醒微小修正会扰乱临界接触，不能据此宣称残差一定改善。

下一步切换到已选定 D03 环境，执行冻结的匹配训练配方，不在最终测试集上改奖励或选择权重。

## 正式实验预案

`artifacts/orca_benchmark_suite/S10/protocol.json` 在示范收集和正式训练前冻结，含输入及源码哈希。

- 三个训练种子：22101、22102、22103。
- 参考示范收集：212000 至 212063，共 64 个初态，只把通过完整标准的轨迹用于 BC。
- 训练中开发评估：211000 至 211015，共 16 个初态。
- 最终策略测试：220000 至 220127，共 128 个共同初态，使用真正末步权重，不按测试结果挑检查点。
- 三种在线方法各 163840 次交互；参考回放不训练，BC 前置 20000 次监督更新另行计入成本。
- 从零手指 PPO：学习率 3e-4、初始探索标准差 0.3；BC 后 PPO：3e-6、0.05；残差 PPO：3e-5、0.1，修正幅度上限 0.08 弧度。
- 本轮使用Brax普通PPO优化器，上述学习率同时用于动作网络和价值网络；没有复用S09专家分支的不同actor/critic学习率插件。网络为两层128单元，32个并行环境；每隔40960次交互检查一次开发集。
- 上述学习率和探索不是完全相同，预算和任务相同；比较的是各自明确记录的配方，不声称隔离了所有优化超参数影响。
- 残差公式中的0.08弧度是网络请求修正的界限。执行器还有限位及每控制周期0.1弧度的目标变化限制，所以日志中的“实际控制减原始参考”不完全等同于PPO输出。零修正预览中该差值也可达约0.033弧度，来源是限速，不是网络暗中给了动作。
- 奖励整轮固定，沿用合格保持、跌落、接触覆盖与释放前接近项，不由大模型在运行中修改。
- 几何对照另外使用 230000 至 230127，四组配对：固定基座单参考、固定基座原六参考选择、已对准预摆位、真实移动对准。这张表与 JAX 策略测试是不同初态生成器和批次，不交叉相减。

## 已完成的示范与核验

正式示范收集的64个初态中59个通过完整标准（92.1875%）；这是训练数据收集成功率，不是最终测试成绩。实际 BC 数据只包含这59条通过的轨迹，所有64个尝试的逐例结果都保留。

`audits/demonstrations_gpu.json` 对保存的4个预览案例（3个成功、1个失败）完成独立原生物理回放：使用相同GPU后端、相同批大小重建初态和完整积分状态，再直接执行已保存控制，所有实际执行步的qpos与接触审计误差均为0。该核验覆盖预览案例，不冒称覆盖全部未保存轨迹。

最初直接在CPU按种子重建初态的检查未通过，保留在 `audits/demonstrations.json`；不同后端和编译方式的微小随机浮点差异能被接触动力学放大。修复的是核验方法，没有修改训练场景、已保存轨迹或成功阈值。

手心视角演示位于 `artifacts/orca_benchmark_suite/S10/renders/`，包括外观与碰撞几何。它们回放真实保存的运动过程，成功片段截到释放后持续合格4秒；文件名及 `render.json` 标明来源，示范收集视频不冒充PPO成果。

最终测试补充说明见[零残差对照补充](零残差对照补充.md)和[路径质量评估补充](路径质量评估补充.md)。它们只补充对照与统计，不改冻结的训练环境、奖励、预算或末步选择规则。

## 已完成的几何对照

以下为另一批128个新初态的配对结果，完整数据在 `alignment_controls/`，不是训练中反复使用的开发集。

| 控制 | 严格成功数 | 成功率 | 所有案例最大接触力 | 成功案例最大接触力 |
|---|---:|---:|---:|---:|
| 固定手，统一使用选中的单参考 | 120/128 | 93.75% | 126.17 N | 27.45 N |
| 固定手，沿用原六参考按朝向选择 | 59/128 | 46.09% | 108.50 N | 19.05 N |
| 已预摆到对准位置，动态位姿控制 | 126/128 | 98.44% | 6.34 N | 6.34 N |
| 从共同远处起点真正移动并对准 | 116/128 | 90.625% | 55.42 N | 9.47 N |

这说明“用同一套相对抓法”在本圆柱上可行，但不能说真实移动组的成功率已超过固定单参考。原六参考按朝向选择也不一定更好；其中较差的模板会拖累整体。

实际移动相对预摆位丢失10个成功，没有新增成功；其中既有较早滑落，也有保持十几秒后滑落，以及虽然曾连续超过30秒但结束时不合格的案例。不能只截取早期稳定画面掩盖长时失败。

实际移动的失败初态230047、230116在接近/抓取过程中分别出现约5.05、5.24毫米最大穿透，故除原释放后门槛外，后续还需单列全回合路径穿透。失败记录保留，不把路径碰撞问题说成已解决。

原模型的前臂外壳只有外观网格，没有新增实体碰撞体，不能把新运动场景称为已经完成全机械臂碰撞建模。为检查当前演示是否利用这一缺口，`audit_s10_forearm_clearance.py` 对保存预览的每个有效控制帧，使用MuJoCo几何距离查询检查三个前臂/安装架CAD凸包与圆柱的间距。最终58条预览记录全部为正，最小约28.95毫米，保存在 `audits/forearm_previews_final/results.json`；包含不同策略及重复核验，不是58个独立初态。这只覆盖已保存20Hz帧，不证明所有未保存案例或5ms子步均安全。[MuJoCo几何距离与凸分解说明](https://mujoco.readthedocs.io/en/stable/computation/index.html)。

移动组的成功案例力峰值低于固定单参考，但这不足以证明实机安全。物体高度与直径均为53毫米，长径比为1，不宜把本结果外推为所有细长圆柱或任意物体的朝向鲁棒性。

在主工程目录、`conda activate aero_rl` 后执行：

```bash
python -m unittest discover -s scripts -p 'test_s10*.py'
python scripts/analyze_s10_study.py
python scripts/verify_s10_delivery.py
```

后两条需要全部训练、测试、视频已经完成，否则会明确失败，不应把缺失组当作0或忽略。训练入口是 `python scripts/run_s10_study.py train`，独立测试入口是 `python scripts/run_s10_ready_evaluations.py`；存在已完成输出时跳过，部分输出不会悄悄覆盖。不要在现有训练进程仍运行时重复启动它们。

不要再次执行冻结命令，也不要修改正式输入或源码后继续混入本轮结果。改动控制器、模型或奖励需要新的实验编号与独立输出目录。

这里的“最适合”是候选参考和规则中经过开发验证选出的方案，不是数学上证明全局最优，也不是对每个测试案例试完所有姿态后挑成功的一个。

## 术语与人话解释

| 术语 | 本实验中是什么意思 |
|---|---|
| 位姿 | 物体或手在哪里，以及朝向哪里。 |
| 相对位姿 | 不管圆柱在世界里怎么放，手相对于圆柱应该在什么位置、朝什么方向。 |
| 坐标归一化 | 把不同世界朝向的观测换成统一的手坐标表达，便于共享一个策略；不是把物体或重力真的旋转掉。 |
| freejoint | 让整手基座具有三个平移、三个旋转自由度。 |
| mocap目标与weld | 一个不参与碰撞的位姿目标，通过柔性约束拉动真实动态手；目标不连接圆柱。可以理解成理想化机械臂末端执行器。 |
| BC，行为克隆 | 用示范里的观测与动作配对训练网络。此版先学习同一参考的时间过程，不等于已经学会救回滑落。 |
| PPO | 在仿真里执行动作、获得奖励，再更新动作网络。 |
| 残差PPO | 每步参考目标加上PPO请求的小修正，之后经过关节限位与限速。参考在执行时仍参与决策。 |
| 从零手指PPO | 手指网络不做BC、也不加参考动作；但与其他组共用整手对准器。 |
| 初态 | 一回合开始时物体的位置、朝向与速度等。 |
| 训练种子 | 控制网络初始化和训练采样的随机数来源。三个种子是三次独立训练，不是三只手同时投票。 |
| 开发集/测试集 | 前者用于选择参考和检查训练；后者在方案固定后评价，不用来回头选赢家。 |
| checkpoint | 某个训练阶段保存下来的网络参数。本正式对比用真正末步，不挑测试分数最高的中间阶段。 |
| 接触力峰值 | 本代码统计各物理子步、各手物接触点的最大法向力，不是整手总夹持力。 |
| 穿透 | 接触求解中碰撞几何重叠的深度；不是看外观贴图凭感觉判断。 |

最直白的理解是：以前让手不动，逼手指适应各种摆法；现在先让整手转过去，让手指面对的相对几何关系尽量相似。BC并没有因此突然获得复杂的纠错能力，而是任务中需要它解决的朝向差异减少了。PPO是否进一步改善，还必须看同批独立测试，不能靠框架名称判断。
