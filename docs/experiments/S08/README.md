## 试了什么方向

| 方案 | 摆法 | 接触方式 |
|---|---|---|
| longitudinal，纵向 | 圆柱轴大致沿手指长度方向 | 尝试手掌＋拇指＋多指侧向包住 |
| transverse，横向 | 圆柱轴横跨手掌宽度方向 | 多指绕圆弧闭合，拇指与掌面共同夹持 |

手腕固定目标为0，掌面大致竖直，物体仍是直径53 mm、高53 mm、35 g；不改碰撞网格、质量、摩擦、求解器来制造成功。位置和抓法不同，因此不能与S07百分比直接排名。

## 什么才算包覆成功

每个5 ms物理子步同时要求：

- 掌面在圆柱曲面侧的法向承力超过0.02 N。
- 拇指的合格掌侧区域承力超过0.02 N。
- 其余四指中至少两指的末节/近节掌侧区域各承力超过0.02 N。
- 不能依赖支撑、地面或其它非手部物体继续托住；手部最大穿透不超过3 mm。
- 3秒撤托后高度损失小于15 mm；连续合格至少30秒，40秒结束时仍合格。
- 初态穿透不能超过1 mm。后面抓稳不能抹去开局不合理的穿插。

“曲面侧”通过接触法向与圆柱轴的点积判断，`abs(normal·axis) <= 0.5`，排除主要从端盖方向支撑。掌面法向在掌局部坐标满足`ny >= 0.6`；手指末节/近节满足`-nx >= 0.4`。这也是针对当前模型的工程定义，不是从人类视频自动读出的标签。

允许其它正常手部辅助接触，不宣称圆弧接触承担了全部重量；要求掌面、拇指和两根对向手指都有曲面夹持载荷，避免把仅仅放在掌上算成包覆。这里允许近节和掌部，而S07要求指定三指末节指腹、禁止掌部承力，两者标准不同。

## 两轮怎么做的

### P01：初始几何尝试

两个方向各6个逆运动学初值，求解所有手指目标，然后从张开状态用1.5秒闭合。每个候选做8秒开发回放，在开发种子8101上选参考，再用81200～81207评估40秒。

结果两个方向均0/8。主要问题是拇指的接触朝向不对，以及部分初态直接与手发生穿插。单纯“末端位置对上”并不能保证用指腹接触。失败结果全部保留在`S08_wrap_pilot/`，没有删除。

### P02：只修几何与摆位，不训练网络

在P01参考上固定其它手指，重新求解拇指，使它既靠近圆柱曲面、又把掌侧朝向物体；初始圆柱沿掌前方向移动6 mm，由真实手指接触把它带入包覆位置，没有给物体加位置伺服或焊接。

两个方向各8个拇指求解初值。用新的开发种子8201选定参考，固定后才评估82200～82207。纵向的6 mm移位仍未消除初始碰撞，故该分支不合格；横向初态穿透为0。

选择按开发得分、几何误差打破平局。横向8个开发候选均未拿稳，但选定参考在新初态中6个成功，说明起手对细小初态变化很敏感；**不能将这8例写成已经充分验证的稳健策略。** 没有看测试结果再换参考。

## 排除了哪些明显假成功

1. 对P02两个方向全部16条轨迹重新运行，逐数组与保存结果一致。
2. 每个物理步检查MuJoCo告警、状态有限性；16条回放均无物理告警。
3. 同场景关闭全部手部碰撞后，横向0.5秒掉落，纵向2.3秒掉落；无等式约束把物体绑到手上。
4. 检查外观与碰撞几何视频，横向确实从张开状态闭合到圆弧包覆；失败起手也保留。

这些检查证明本次仿真不是靠隐藏连接维持，但不等于已证明硬件可用。摩擦标定、软指腹形变、力矩限制和真实控制延迟仍需另行验证。

## 前期提出的接口方案（后续完成状态见页首）

本轮包覆参考是手工定义几何目标加逆运动学，不冒充新的视频重定向。要把它变为用户原来的视频引导实验，下一步应从匹配包覆抓法的视频/处理后示范中提取掌面与多指物体相对关系，再重定向并做同样的接触验证。

之后可以沿用三分支结构，但要新建包覆环境和示范集：

- 纯PPO：共同包覆奖励下输出完整动作。
- BC+PPO：有效包覆执行生成状态/动作对，BC初始化，再做在线PPO。
- 残差PPO：每步包覆参考＋有界PPO修正，参考和修正显式相加。

当前NPZ具有`ctrl/time/initial_ctrl/object_position/object_quaternion`等参考接口字段，可作为后续适配的起点；**不能直接把它塞进S07就声称兼容**，因为S07会把掌部接触判成失败，观测、奖励、示范绑定哈希也需要在新任务版本里一致更新。

最先该修的是两个早期掉落案例的初始支撑与闭合时序，而不是立即长训后宣称PPO补好了几何问题。若在包覆任务正式比较算法，还要使用相同奖励、相同在线预算、多训练种子和新的独立测试初态。
