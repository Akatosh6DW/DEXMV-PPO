先区分两件事：参考文件决定基础动作，神经网络权重决定学习到的动作或修正。NPZ不是网络权重；本轮几何参考不等于新的视频重定向结果。

参考生成部分的数学原理、实际TRF求解器以及S05至S08的来源差异，见[逆运动学与参考生成原理](逆运动学与参考生成原理.md)。

## 一步动作如何落到物理仿真

```text
当前观测 obs
  -> 策略网络输出归一化动作
  -> 纯PPO/BC+PPO：映射为完整关节目标
     残差PPO：参考目标 + 0.08 rad以内的修正
  -> 关节范围裁剪、每50 ms最大变化0.1 rad
  -> 原生MuJoCo推进10个5 ms物理子步
  -> 逐子步读取真实接触法向载荷、几何法向、穿透
  -> 区间内取最小承力、最大穿透和禁止接触并集
  -> 算奖励、更新连续保持计数、返回新观测
```

`WrapPhysics`不是新的策略。它是仿真审计层，负责确保指腹只接触一瞬间不能被当成整个50 ms都稳定。

`WrapData.wrap_loads`的6个位置依次是掌面、拇指、食指、中指、无名指、小指。需要前两组过阈值，以及后四组至少两组过阈值。

## 为什么还有很多cube、pad、video名字

这些是共享代码保留的字段名：`cube_z`表示当前目标物体高度，本轮实际模型类型是圆柱；`pad_hold_sec`在S08表示满足包覆判据的连续保持；`video_base`在S08存的是几何参考目标，不表示此时读了RGB视频。

适配器保留字段，方便复用网络尺寸、示范格式和旧统计工具；**字段兼容不代表任务和来源相同**。新环境单独定义掌面规则、15 mm高度阈值和1 mm初始穿透门限。

## 哪些参数控制什么

- `--steps 163840`：所有并行环境累计在线交互数，不是回合数。
- `--evals 9`：包括0步在内的开发检查次数。
- `--bc-updates 20000`：BC的离线梯度更新数，不属于PPO在线步数。
- `--residual-bound .08`：单关节最大请求修正弧度，不是每秒累计。
- `--residual-gain 0/.5/1`：执行时关掉/减半/保留修正，不重新训练。
- `--benchmark`：测试条件，改变位置范围、摩擦等；同条件所有方法共用相同初态。

## 最容易误读的地方

1. `guided`只是内部方法名，表示BC+PPO，不是把参考强制相加；`residual`才是执行端相加。
2. `step_000000000`对guided表示完成BC但尚未在线PPO，不应当成PPO成绩。
3. 学习曲线的最高成功率可能发生在0步参考/BC状态；正式PPO选模只从正步数中选择。
4. `summary.json`说明任务进程完成，不能单独证明整个实验完成；还要检查独立评估、配对初态、源文件哈希和轨迹复算。
5. 展示视频只剪前几秒，但完整成功依据40秒轨迹的30秒保持；不能由短片长度推断只测了4秒。

## 原工程与资料包

源码在原工程可结合`aero_rl`环境和原始资产运行。资料包重点用于理解与分析，不带权重和完整STL资产；它不是独立部署包。源文件快照保存在各运行数据的`sources/`目录，记录的是当次实际加载的代码，便于追溯。
