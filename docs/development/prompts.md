# 可复用项目提示词

这些是本工程可共享的任务模板，不是任何工具的内部提示词，也不包含私人对话原文、账号凭据或密钥。旧 Aero-Hand 开发提示词仍在其 `v2_iteration_docs/prompts/` 与 `VT_continuation_prompt.txt`；它们记录当时目标，不覆盖最新冻结协议。

## 新开发者接手

> 先读 README、docs/development/README.md、CONTRIBUTING.md、目标实验协议与结果。检查 Git 状态，不覆盖他人的改动。说明正在研究哪个任务、使用何种手型、物体、观测和动作。按发布清单核对参考、样本、权重、源码哈希，先跑 CPU 接口验证，再做一次单初态策略评估。区分历史结论与本轮待验证假设，指出缺失依赖，不编造成果。

## 受控强化学习迭代

> 为新实验建立独立编号和输出目录。提出一个能被证伪的机制猜想，列出现有证据、对照组、预期观测以及失败时如何否定。每轮只改少量变量。冻结开发/保留测试划分，先短探测再多种子确认。保存参数、配置、数据来源、动作语义、日志和逐例结果。不得用保留测试反复挑最优参数；不得将未训练的参考回放当多个独立训练种子。

## BC 退化诊断

> 对比配对 BC 起点与 PPO 后网络，先核对归一化、动作尺度、初态分布、奖励和接触判据。检查动作漂移发生在哪个阶段、哪几个关节；分别冻结/替换 phase 主干与状态反馈进行机制探测，记录这只是诊断还是新训练组。区分示范只是相位动作序列、还是覆盖失败恢复状态的反馈专家。只有独立实验支持时才断言原因。

## 残差架构检查

> 明确 q_target = clip(q_reference(phase) + bound * action_PPO)，以及之后的限位和限速。验证零残差与参考完全一致、非零残差改变实际执行量；同时记录请求修正和最终有效修正。不能只凭网络输出不为零就宣称改进，应与同初态参考回放配对比较。

## 汇报与发布

> 用人话说明任务、源示范、重定向/几何校正、BC、PPO、残差各自做什么。给出总分母、逐种子结果、配对差异、失败分类及限制。保留负结果。索引权重、输入、场景、数据、代码和视频，用 SHA 去重；在全新路径验证可运行。逐项说明哪些上传、哪些因重复/许可/隐私/无效被排除。不要把“能加载”写成“已复现成功率”。
