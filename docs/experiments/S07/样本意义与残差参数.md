# 样本不像了，是不是就没意义？残差到底怎么给？

## 先给直接答案

**不一定没意义，但不能只凭“抓住了”就认定视频发挥了作用。**

假设视频展示用拇指和食指指腹夹住物体，最终机器人却靠手指侧面卡住：任务层面可能成功，但示范抓法没有复现。尤其是残差架构，如果基准本来就重定向错了，小修正只是在错误抓法附近优化，不能替重定向证明正确。

反过来，人的手与 Orca 长度、关节、安装位置不同，最终关节角不一样很正常。真正值得保留的是“哪些手指从哪几侧接近物体、用哪一面承力、何时合拢”，而不是逐个照搬人手角度。

## 三种不同的“像”

| 要比较什么 | 人话解释 | 不能代替什么 |
|---|---|---|
| 位置接近 | 指尖在物体周围的位置是否接近样本 | 指尖中心对上，不代表指腹朝向正确 |
| 姿态/朝向接近 | 指腹是否面向物体，而不是横着过去 | 面向物体不代表真有接触或承担了重量 |
| 接触方式接近 | 指腹、侧面、近节，究竟哪一块实际承力 | 接触方式一样，也不保证能稳定保持 |

因此，成功率和示范相似度必须分开报告。一个策略可以“抓得住但不像”，也可以“摆得像但拿不住”。对于当前有源重建穿插的圆柱数据，一味降低点位误差甚至可能让仿真更不合理。

## 当前样本实际贡献了什么

源文件是 DexMV 发布的 `relocate-tomato_soup_can.pkl` 中处理后的 Adroit 示范。圆柱沿用序列 96 的 182–271 帧。不是直接把真人视频像素送给 PPO，也不是视频直接生成了一个万能策略。

实际链路是：

```text
处理后的源手轨迹
  -> 提取物体相对的三指目标关系
  -> 根据 Orca 的长度、关节范围和指腹方向做重定向
  -> 仿真中有界校正，得到可执行参考
  -> 两种使用方法：
       参考成功执行 -> 观测/动作样本 -> BC -> PPO
       每步读取参考基准 + PPO 输出有界修正 -> 执行
```

S06 的源重建是多指包覆，不是干净的两指夹持；部分手指严重穿入物体。因此选择“拇指对向食指和中指”的三指适配目标，不声称完整复刻五指人手。物体也进行了尺寸适配。参考中的几何适配、初始腕位和仿真校正都是额外工程贡献，不能统称为“纯视频效果”。

核对保留文件后，**离线仿真校正相对未校正 IK 参考的最大关节变化约 0.22588 rad（12.94°）**，大于执行时 PPO 允许的单关节 0.08 rad（4.58°）修正上限。这两个步骤不能混在一起：较大的可执行性修复主要在离线参考生成时完成；训练中的残差负责围绕已经修复的参考反馈调整。最终效果不能只归给视频，也不能只归给 PPO。

纯 PPO 的动作和观测中不输入参考动作，但三方法共享由开发过程选定的场景、物体工作区和初始腕姿。它是共同场景下的无示范控制基线，不是连场景设计都完全与示范无关。

另外，共同奖励已经明确指定“拇指、食指、中指的指腹承力”。这也是人设计的任务知识，纯PPO同样享有；三个手指的选择并不是在线网络自动从视频里发现的。因此对比回答的是“在共同任务设计上，加示范初始化或动作基准有什么作用”，不是严格剥离所有人类先验后的比较。

本任务是固定安装的单手，圆柱初始由支撑托在工作区，手闭合后撤托再保持。没有机械臂从任意桌面位置接近、抬升、搬运的动作，因此“抓持成功”不应写成已经解决完整桌面拾取。B2 的绕圆柱轴旋转也需谨慎解释：理想圆柱轴对称，几何形状不变，主要改变位姿表示/局部方向，不是不同形状泛化。

**当前基准是按时间读取的离线轨迹，不是能根据新物体自行选动作的通用视频策略。** PPO 根据关节、物体状态和仿真触觉反馈调整；执行时没有读取新 RGB 图像。更准确的名称是“视频先验引导的状态反馈残差控制”。大幅移动物体或换尺寸后，固定参考可能失效；要扩展成实时视觉闭环，还需要视觉状态估计和随物体状态更新的基准生成器。

## 为什么残差也可能抓得不像

1. **基准错了。** 之前只对齐末端点位，没有严格约束实际指腹承力。末端球形碰撞体的侧面也能接触。
2. **角度小不等于接触变化小。** 接触是离散变化：很小的转动可能使一个接触消失、另一个出现。17 个关节同时各改几度，末端位移也会叠加。
3. **目标角不是实际角。** 控制器发目标，物体反力、关节速度和执行器力限制共同决定真实姿态。
4. **奖励只管它写进去的东西。** 如果奖励只要求不掉落，就没有理由期待它自动保持人类抓法。当前新增的三指末节指腹判据才表达了这一要求。
5. **源样本也有误差。** 单目/处理后重建并不是接触真值，机器人为了可执行必须作出偏离。

所以残差只承诺控制形式是“基准＋修正”，不天然承诺外观、接触、任务语义都忠实于视频。

## 当前执行公式

记 $b_t$ 为重定向并仿真校正后的基准关节目标，$o_t$ 为当前观测，网络输出 $a_t=\pi_\theta(o_t)$：

$$
\Delta q_t=0.08\,\mathrm{clip}(g a_t,-1,1)
$$

$$
d_t=\mathrm{clip}(b_t+\Delta q_t,q_{\min},q_{\max})
$$

$$
u_t=\mathrm{clip}(d_t,u_{t-1}-0.10,u_{t-1}+0.10)
$$

- $g$ 是执行时残差增益，正常训练和执行为 1；干预实验取 0、0.5。
- $u_t$ 是发给位置执行器的目标角，不是实际测得关节角。
- 每一步从当步 $b_t$ 出发，**不是**把修正不断累加到上一步目标上。
- 最后两个裁剪依次保证关节目标不越界、变化不太快。
- 日志 `requested_residual` 对应 $\Delta q_t$；`effective_residual` 对应 $u_t-b_t$。受到边界/变化速度限制时二者不相等；不能把请求上限直接当作所有实际关节姿态的误差上限。

例如基准某关节 0.70 rad，网络输出 0.5，正常修正为 0.04 rad，候选目标是 0.74 rad。如果上一步目标仅 0.50 rad，速度限制会使本步实际目标先到 0.60 rad。物理上的关节角还要由执行器和接触反力决定。

BC+PPO 则是先拟合示范动作初始化网络，再由 PPO 修改网络参数。执行时直接输出完整目标，没有必须加在参考上的约束。因此它可能保留、改善，也可能遗忘原来的抓法。

## 参数怎么来的

| 参数 | 当前值 | 含义与选择依据 |
|---|---:|---|
| 修正维度 | 17 | 对应 Orca 的 17 个控制量，包括腕和手指；不等于每个手指一个数 |
| 单维修正上限 | 0.08 rad，约 4.58° | 沿用已验证的工程设置，给局部补偿空间；不是视频估计值，也没有证明是最优值 |
| 残差增益 | 1 | 正常发挥网络输出；0 关闭、0.5 减半，用于测贡献，不冒称重新训练的上限搜索 |
| 目标每步最大变化 | 0.10 rad，约 5.73° | 所有方法共享的平滑执行限制，50 ms 一步，约 2 rad/s 的目标变化上限 |
| 控制周期 / 物理步长 | 50 ms / 5 ms | 每次网络决策后物理积分 10 次，并在每个物理子步检查接触 |
| 基准闭合时长 | 1.5 s | 适配后的参考节奏；之后保持末端目标，PPO 仍每步修正，不是每步看新视频 |
| 初始策略标准差 | 0.1 | 用于训练探索的分布参数；不能简单当成真实关节角的 0.1 rad 噪声 |
| PPO 学习率 | 1e-4 | S07 三方法统一，用于受控比较；S06 曾单独试过 BC+PPO 的 1e-5，不能混进统一学习率结果 |
| 在线预算 | 163840 步/种子 | 为对齐既有方块比较设置，不是理论最优训练步数；三个方法同预算 |
| BC 更新 | 20000 次 | 只给 BC/BC+PPO，属于额外离线成本；不是与 PPO 环境步等价的数量 |

如要选更合适的残差上限，应在开发集固定其它配置，分别用 0.04、0.08、0.12 等从头训练，比较多个随机种子的稳定性、饱和比例、动作偏离和成功率，再用没参与调参的初态测试。太小可能救不了错误参考，太大可能改变抓法或把整个任务留给 PPO。S07 的增益干预不等价于完成这项重训搜索。

三方法的标准差数值相同，不代表实际关节探索幅度相同：完整动作会映射到整个关节范围，残差只映射到参考附近；策略输出经过非线性和裁剪，靠近关节边界时探索也会收缩。纯 PPO 采用接近张开起手的输出初始化，残差采用零修正初始化，BC+PPO 采用示范初始化。这些是整套方法的真实差别，也是不能把一次固定配置的排名解释成所有 PPO 配置排名的原因。

奖励里没有直接追逐视频关节角的损失，也没有运行时不断调整奖励。相似性主要来自基准动作结构与显式接触要求。如果以后增加示范距离惩罚，应该单列为新方法并做消融，避免把穿插的源样本当作必须精确复现的目标。

## 怎么证明样本真的有帮助

最直接的证据不是某张相似截图，而是同场景、同初态的对照：

- 参考本身与残差策略比，测在线修正是否真的救回了回合，同时是否也弄坏了一些原本能成功的回合。
- 未校正参考与校正参考比，测仿真校正的作用；不能把这一段贡献全算给 PPO。
- 完整参考与同终点线性闭合比，测中间时序是否必要；即使线性效果相当，也只说明完整时序未显示额外价值，不代表终态先验无用。
- 纯 PPO 与两种利用示范的方法比，测共同预算下整套方案的效果；BC 预训练和参考优化是额外成本。

更严格地证明“视频比任何非视频先验更好”，还需要给手工/随机初始化的参考同样的离线优化预算，再做独立对比。本轮没有这项匹配成本的无视频先验对照，所以无论结果多好，都不应写“视频不可替代”。

## 圆柱的指腹和指尖是怎么定义的

不是贴图颜色，也不是只看碰撞体名字是否包含 `tip`。环境读取真实接触点和法向力，把接触转到对应末节局部坐标：

- 必须属于拇指、食指、中指各自末节。
- 接触点局部 Z：拇指至少 15 mm；食指、中指至少 24 mm，排除靠近关节的区域。
- 从手指指向物体的法向满足 `-nx >= 0.7` 且 `abs(ny) <= 0.5`，即朝屈曲侧而非侧面。
- 三指合格部位各承力超过 0.02 N，同时这些手指非合格部位不能超过该阈值。
- 每个 5 ms 子步都满足才计入连续有效抓持；还需撤托、高度和其它安全条件。

这是一套有坐标依据、能被代码检查的工程定义，不是声称从源视频准确测到了真人指腹的皮肤区域。源码见 `scripts/orca_s06_env.py` 中 `cylinder_contacts` 与 `CylinderPhysics`，S07 继承相同判据。
